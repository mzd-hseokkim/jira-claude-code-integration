### Info

1. **Story 폴백 + Subtask 폴백 다중 폴백 누적 케이스**: 6-1b 의사코드(L515-517)에서 Story 비활성 폴백은 `issue_type = "Task"` + `parent = Epic-KEY`로 처리한다. 6-3에서 Subtask 폴백 분기가 일어나면 `issue_type = "Task"` + `parent = (폴백된 Story Task의 키)`로 누적된다. 동작은 정의되지만, "Task with parent=Task with parent=Epic" 다중 계층 폴백을 별도로 다루지 않으므로 회귀 테스트 후보로 남겨둘 가치가 있다. (블로커 아님 — 기존 분기로 동작 보장됨)

2. **`AskUserQuestion`이 frontmatter `allowed-tools`에 미명시**: SKILL frontmatter L6-19에 `AskUserQuestion`이 빠져 있는데, 본 스킬은 Step 2/4/5/E1/E4/E6 등 다수 지점에서 호출한다. 이번 변경에서 도입된 문제는 아니지만, 다른 jira-task-* 스킬들과 함께 일관 처리해 두면 안전하다.

3. **Import 모드 자연어 힌트의 description 결합 절차 미상**: Step 0(L125-127)에서 `--from-requirements`와 자연어 힌트가 동시일 때 "import 우선, 자연어 힌트는 Epic description의 추가 컨텍스트로만 사용"한다고 했지만, 실제로 어느 위치에 어떤 형식으로 합쳐지는지(예: Epic description 끝에 별도 단락) 절차가 없다. LLM 추론에 의존한다. 명세 결정성을 더 높이고 싶다면 후속 보완 후보.

## Positive Notes

- **회귀 방지 안내가 강력**: Step 3/4 skip 안내에 "회귀 금지" 문구를 명시해 LLM이 import 모드에서 자동 분해 판단으로 빠지는 회귀를 명시적으로 차단한다.
- **방향성 주의의 친절함**: `(blocks: X)`의 의미를 "N이 X를 블록한다"가 아니라 "N is blocked by X"임을 별도 인용 블록으로 강조(L596-598). 매우 흔한 혼동 지점이라 명세적 가치가 높다. 이전 리뷰에서 지적되었던 단락 내 모순도 모두 정리되어 outward/inward 정의가 일관된다.
- **E8(중복 summary) 모드별 검사 시점 분리**: import 모드는 Preview 직전 일괄 JQL, default 모드는 Step 6 직전 1건씩(L385, L679). 일괄 검사로 N+1 네트워크 호출을 줄이는 합리적 최적화. 이전 리뷰에서 누락 지적된 부분이 명확히 보강됨.
- **priority/labels 추출 규칙 명시**(L200): 표준 트리 형식에 priority/labels 표기 문법이 없다는 점과, 폴백으로 항상 `Medium` + 옵셔널 처리한다는 점을 명문화. 이전 리뷰의 Warning 항목이 정밀하게 해소됨.
- **Tree 형식의 변형 허용 (들여쓰기 2/4-space, 불릿 `-`/`*`)**: 디스커버 산출물의 다양한 표기를 수용하면서 첫 자식 들여쓰기 폭을 기준으로 일관성 검사하는 규칙(E10)이 견고하다.
- **자료 구조(`ImportPayload`)를 LLM이 머릿속으로 들고 가는 추상 모델로 명시**: 코드가 아닌 명세에 자료 구조를 두는 방식이 적절히 표현되어 LLM의 행동 일관성을 높인다.
- **discover ↔ create 정합성 약속 명시**: L137에서 discover Step 6 안내 메시지와의 형식 일치를 "정합성 약속"으로 못 박았다. 향후 한쪽만 수정해서 깨지는 회귀를 막는 좋은 가드.
