### Info
- `done.requires: ["pr"]`은 worktree 환경(로컬 merge → PR)에 맞춘 정의. remote가 없는 워크플로에서는 customize가 필요하지만, 그 책임은 `_comment`의 "복사 후 수정" 가이드로 위임됨. 설계 Edge Cases에서 이미 인지 — 본 작업 범위 외.
- `merge.requires: ["review"]`로 정의되어 있어 phase-gate가 활성화되면 review 미통과 시 merge가 차단된다 — 설계 의도와 일치하나, 후속 MAE-123에서 bypass 메커니즘이 함께 작동해야 사용성이 유지됨. 본 작업의 책임은 아님.
- 표기 일관성: `merge` / `pr` / `done`은 description의 "merge: review 통과", "pr: merge", "done: pr"과 동일. 다른 표기(예: `localMerge`)를 쓰지 않아 후속 통합이 단순.

## Positive Notes

- 설계 `Data Model` 섹션의 12단계 정의표와 JSON이 1:1 매칭 — 후속 MAE-123 구현자가 다른 문서를 교차 참조하지 않아도 됨.
- `_comment` 필드를 사용한 인라인 가이드는 JSON의 no-comment 제약을 우아하게 우회 (관례적 패턴).
- `version: "1.0"` 메타필드를 처음부터 포함 — 향후 스키마 변경 시 마이그레이션 hook을 두기 쉬움.
- `enforced: false`를 `discover`/`create`에 적용해 init 이전 단계에서의 phase-gate 오작동 가능성을 사전 차단.
- artifact 패턴에 `{TASK_ID}` placeholder를 명시 — MAE-123이 어떤 치환 책임을 갖는지 명확.
- README 변경이 최소(트리 한 줄 + 짧은 섹션)이고 다른 섹션과 자연스럽게 어울림.
