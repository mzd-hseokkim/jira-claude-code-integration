### Warnings

- `skills/jira-task-review/SKILL.md:117` — `${BASH_SOURCE[0]:-$0}`을 사용하지만 SKILL.md의 Bash 블록은 Claude의 `Bash` 도구로 직접 실행되며 BASH_SOURCE는 비어 있고 `$0`도 의미 있는 경로가 아닐 가능성이 높다. L120의 fallback `skills/jira-task-review/SKILL.md`(cwd 기준 상대경로)에 사실상 항상 의존하게 된다. 워크트리 cwd가 repoRoot가 아닌 하위 디렉터리일 경우 reviewerVersion="unknown"으로 떨어진다. 의도가 fallback이라면 L117-120 주석을 "always falls back" 으로 정정하거나, `.jira-context.json`의 `repoRoot`로부터 절대경로 산출하는 편이 견고.

- `skills/jira-task-review/SKILL.md:142` — `scripts_dir = os.path.join(os.getcwd(), "scripts")`도 동일한 cwd 가정. 워크트리 루트에서 review를 실행한다는 암묵적 전제가 있고, 그렇지 않으면 redact 모듈 import 실패 → AC-6 미달(원문 그대로 저장)로 silent degrade. 경고는 출력되나 redact 미적용 사실이 entry 내부에 표식 없이 저장되어, 후속 분석 시 "false negative leak"가 검출되지 않을 수 있다. 최소한 redact 미적용 entry에 메타필드(`redactApplied: false` 등)를 두거나, `.jira-context.json.repoRoot`를 우선 사용하도록 보강 권고.

- `skills/jira-task-review/SKILL.md:126` — `trap 'rm -f "$TMPFILE"' EXIT`를 Step 4.7 블록 진입 시 설정하지만 후속 Step 4.5/Step 5도 같은 main 세션에서 동작하므로 이 trap이 다른 후속 블록의 EXIT trap과 충돌하거나 덮어쓸 수 있다. 단일 Bash 실행 단위 안에서만 안전하지만, SKILL.md의 코드 블록이 별개 Bash 호출로 실행될 가능성 높음 → 실 영향은 없으나, trap 사용은 개별 블록 내부 cleanup이 더 명확. `rm -f "$TMPFILE"`을 `set -e` 직전에 명시적으로 호출하는 편이 의도가 분명.

- `scripts/review_log/redact.py:24` — `aws_secret_key` 패턴 `[A-Za-z0-9/+=]{40}`은 capture group을 가지지만 `pattern.sub` 치환은 전체 매치를 `***REDACTED:aws_secret_key***`로 바꾼다. 즉 `aws_secret_access_key=ABC...XYZ`(40자) 전체가 라벨로 바뀌어 키 이름 컨텍스트도 사라진다. 동작은 안전(과치환 방향)하지만, 분석 시 어떤 토큰 종류였는지 키 이름 정보가 사라지는 부작용.
