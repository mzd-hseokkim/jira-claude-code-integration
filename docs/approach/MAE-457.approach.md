# Approach: MAE-457 - [TEST-3] tests/review_log/test_redact.py가 unittest discover로 실행되도록 수정

- **Level**: L1 (Single)
- **Source**: N/A — discover 생략, Jira 이슈 설명 + 실패 재현 로그

## Approach (L1 Single)

- **변경 영역**: `tests/review_log/test_redact.py` 상단 import 블록만 (line 8~18). `scripts/` 및 다른 테스트 파일은 손대지 않는다.
- **핵심 결정**: `sys.path` 조작 대신 `importlib.util.spec_from_file_location`으로 `scripts/review_log/redact.py`를 파일 경로에서 직접 로드 — 실패 원인이 경로 누락이 아니라 **패키지 이름 충돌**이기 때문. `discover tests`는 top-level dir이 `tests/`라서 `tests/review_log/`가 top-level 패키지 `review_log`로 먼저 등록되고, 이것이 `scripts/review_log`를 가려 `review_log.redact`를 못 찾는다(`sys.path`에 `scripts/`를 넣어도 `sys.modules["review_log"]`가 이미 선점됨). 기각한 대안: `tests/review_log/__init__.py` 삭제(디렉터리 구조 변경 + 다른 discover 경로 회귀 위험), 테스트 디렉터리 rename(이슈 범위 밖).
- **검증**: 레포 루트에서 `python -m unittest discover tests`가 errors=0으로 통과하고, `python -m unittest tests.review_log.test_redact`도 15 tests OK 유지 — 두 경로 모두 실행해 대조한다.
- **리스크**: 낮음. importlib 로드는 모듈을 `sys.modules`에 등록하지 않아도 되므로 다른 테스트의 import 상태에 영향이 없다. 다만 `redact.py`가 향후 동일 패키지 내 상대 import를 추가하면 파일 단위 로드가 깨질 수 있어, 그때는 `sys.modules` 등록을 병행해야 한다.
- **롤백**: 단일 파일 import 블록 한정 변경이므로 `git revert` 한 번으로 원복 가능. 프로덕션 코드 영향 없음.
