# Approach: MAE-412 - Level-aware ceremony를 impl/test/review로 확장

- **Level**: L2 (Story)
- **Source**: N/A — discover 생략 (Jira description의 무엇을/왜/목표/대상 파일을 입력으로 사용)

## Approach Summary (L2 Story)

현재 `approach` 스킬만 L1/L2/L3 레벨에 따라 산출물 분량·ceremony를 조정한다. 같은 level 손잡이를 후속 `impl`/`test`/`review` 스킬로 전파해, L1 작업이 풀 test-report·gap-analysis 템플릿을 강요받지 않도록 한다. 핵심은 단일 진실원천(`.jira-context.json.breakdownLevel`)을 후속 스킬이 동일한 규칙으로 읽고, 레벨별로 산출물 경량화(L1 인라인 가능) / 현행 유지(L2) / child Story 매핑(L3) 분기를 추가하는 것. 코드가 아니라 prompt 마크다운이므로 "분기를 어디에 박고, 무엇을 SSOT로 두는가"가 비가역 결정이다.

## Architecture

비가역 seam = **레벨 판정 로직의 단일 출처**. approach가 이미 Step 0에서 `breakdownLevel` → issuetype 폴백 순으로 판정하는 규칙을 갖고 있다. impl/test/review는 이 규칙을 **재구현하지 않고 참조**해야 중복·드리프트를 막는다.

```
.jira-context.json.breakdownLevel  ← SSOT (create/approach가 기록)
        │  (없으면 issuetype 폴백 — approach Step 0 규칙 인용)
        ├─ impl   : Implementation Plan(L2) vs 5줄(L1) vs child위임(L3) — 이미 일부 존재, 명문화
        ├─ test   : L1=경량 검증(인라인 가능, report 생략 허용) / L2=현행 / L3=child별
        └─ review : L1=핵심 findings만(gap-analysis 경량) / L2=현행 / L3=child별
```

레벨 읽기는 각 스킬 Step 1(Load Context)에서 1회 수행하고, 산출물 생성 Step에서 분기. 판정 규칙 본문은 approach Step 0를 "동일 규칙 적용"으로 짧게 참조(복붙 금지 — 토큰·드리프트).

## Key Decisions

| # | 결정 | 대안 | 선택 이유 |
|---|---|---|---|
| 1 | level SSOT = `.jira-context.json.breakdownLevel`, 폴백은 approach Step 0 규칙 참조 | 각 스킬이 자체 판정 재구현 | 중복·드리프트 방지. 출처: "level을 전 단계로 퍼뜨리는 spine" (description) |
| 2 | 판정 규칙은 참조, 복붙 금지 | 각 SKILL.md에 Step 0 전문 복사 | prompt 분량=토큰비용 (CLAUDE.md Simplicity First) |
| 3 | 템플릿은 옵셔널 마커로 L1 경량화, 별도 L1 템플릿 신설 안 함 | L1 전용 template 파일 추가 | 템플릿 수 증가·유지비. 기존 옵셔널 마커 규약 재사용 |
| 4 | L1 test/review 산출물은 인라인(파일 생략) 허용 | 항상 파일 생성 강제 | L1 역효과(토큰 낭비) 제거가 본 작업의 동기 (description "왜") |

설계 차원 ruling: 데이터 모델/스키마 — 해당 없음. 트랜잭션 — 해당 없음. **인터페이스/계약 — 해당** (스킬 간 `.jira-context.json` 읽기 계약, 결정 #1). 동시성 — 해당 없음. 보안 — 해당 없음.

## Test Plan

| # | 케이스 | 검증 |
|--|--|--|
| T1 | L1 task로 test 실행 → report 인라인/생략 경로 동작, 풀 템플릿 강요 안 함 | 목표 L1 |
| T2 | L1 task로 review 실행 → gap-analysis 경량 findings만 | 목표 L1 |
| T3 | L2 task로 impl/test/review 실행 → 현행과 동일 산출물 | 목표 L2 회귀 없음 |
| T4 | `breakdownLevel` 미존재 task → issuetype 폴백으로 동일 판정 | SSOT/폴백 일관성 |
| T5 | plugin.json version 증가 확인 | 버전 동기화 규칙 |

스킬은 prompt이므로 "테스트"는 대표 task로 dry-run하여 분기 문구가 의도대로 읽히는지 검증.
