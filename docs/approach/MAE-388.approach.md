# Approach: MAE-388 - Phase 3 — SDLC·에이전트 처리량 조인 + 퍼널/priority·epic 파생

- **Level**: L2 (Story)
- **Source**: N/A — discover 생략 (Jira description 기반)

## Approach Summary (L2 Story)

Phase 1/2에서 만든 두 데이터 소스를 이슈 key로 조인해 이 대시보드 고유 지표를 완성한다. (1) worktree activity store(`store.js`)의 `completedSteps`·PostToolUse 이벤트 수를 metrics store(`metrics-store.js`)의 Jira 이슈에 `taskId === issueKey`로 매칭해 SDLC·에이전트 처리량을 집계하고, PDCA 단계 퍼널(어느 단계에 몇 건이 머무는가)을 산출한다. (2) 이미 수집 중인 `priority`와 (현재 미수집인) `epic`을 파생 집계해 priority 분포·epic별 진행률 차트를 추가한다. 모든 신규 지표는 기존 `/metrics` 응답에 필드를 더하고 `AnalyticsView`에 섹션을 붙이는 방식으로 확장한다.

## Architecture

핵심 seam은 **두 store의 조인 경계**다. metrics store는 영속(SQLite/JSON, `issueKey`/`spaceId` 키), worktree activity store는 휘발(in-memory RingBuffer, `worktreePath`/`taskId` 키). 조인은 `routes/metrics.js` 레이어에서 수행 — metrics 라우터에 worktree store 핸들(또는 그 snapshot accessor)을 DI로 주입하고, 응답 조립 시 `spaceId`의 projectKey 접두사로 worktree snapshot을 필터·매칭한다. metrics-store와 worktree-store는 서로 모른 채 유지(결합 방지). priority/epic 파생은 metrics-store 내부 SQL/JS 집계로 닫힌다 — 조인 불필요.

```
metrics-store (영속, issueKey)  ─┐
                                 ├─> routes/metrics.js (조인 by taskId===issueKey) ─> /metrics JSON ─> AnalyticsView
worktree store (휘발, taskId)  ─┘
```

## Key Decisions

| # | 결정 | 대안 | 선택 이유 |
|---|---|---|---|
| 1 | 두 store 조인을 routes/metrics.js 레이어에서 수행 | metrics-store가 worktree store를 직접 import | 영속/휘발 store 결합 방지; 기존 라우터가 이미 조립 지점 (FR: SDLC·에이전트 처리량 조인) |
| 2 | 조인 키 = `taskId === issueKey`, spaceId projectKey 접두사로 스코프 | worktreePath 매핑 테이블 신규 | taskId가 곧 issueKey라 추가 매핑 불필요; "로컬 worktree 있는 이슈에 한함" 요구와 일치 |
| 3 | epic을 `issue_current.epic` 컬럼에 채워 영속화 (스키마 이미 존재) | 응답 시점 매번 파생 | 컬럼·인덱스가 이미 스키마에 있음; 재집계 비용 회피 (AC: epic별 진행률) |
| 4 | 에이전트 tool-call 수는 in-memory snapshot의 근사값으로 노출 | 전 이벤트 영속화 | activity는 RingBuffer(최근 50)·휘발 — 영속화는 Phase 3 범위 밖, 근사로 AC 충족 (Risk R1) |
| 5 | 퍼널 단계는 기존 `SDLC_STEPS`(7단계) 재사용 | 별도 퍼널 단계 정의 | 단일 출처 유지, Stepper와 일관 |

## Risks

| Risk | Impact | Mitigation |
|------|--------|------------|
| R1: activity store 휘발·RingBuffer(50) → tool-call 수가 세션/재기동에 따라 부분값 | 에이전트 처리량이 절대값 아닌 근사 | "최근 활동 기준 근사" 라벨 표기 (cycleTime `note` 패턴 답습); 영속화는 후속 과제 |
| R2: epic 커스텀 필드 ID가 Jira 인스턴스마다 다름 | epic 추출 실패 | parent 체인 폴백 + 추출 실패 시 null·차트 graceful empty |
| R3: taskId↔issueKey 매칭 시 projectKey 불일치 스페이스 누락 | 잘못된 스페이스 집계 | spaceId projectKey 접두사 필터로 스코프, 미스는 제외 |
