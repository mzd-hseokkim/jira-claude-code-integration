# Plan: MAE-173 - [1.3.5] plan.template.md 통일 + 5개 SKILL.md 강화 (MAE-174 흡수)

## Background

MAE-128에서 신규 4종 template(`design`/`test-report`/`review`/`pr-description`)에는 contract 주석 + 옵셔널 마커 규약을 적용했으나 `templates/plan.template.md`는 옛 패러다임 그대로 남아있다. 외부 리뷰에서 일관성 갭으로 지적됨.

본 작업은 원래 MAE-173(plan.template.md 통일)에 MAE-174(5개 SKILL.md 강화)를 흡수하여 진행한다. 둘 다 plan.template.md/SKILL.md 정리라는 결이 같고, 분리 진행 시 SKILL.md를 두 번 만지게 되어 비효율적이다.

## Scope

### In Scope

1. **`templates/plan.template.md` 통일**: 신규 4종과 동일한 형식으로 contract 주석(필수/권장/옵셔널 분류) + 옵셔널 마커(`<!-- optional: ... -->`) 추가
2. **5개 SKILL.md template 참조 강화**: `jira-task-plan/SKILL.md`, `jira-task-design/SKILL.md`, `jira-task-test/SKILL.md`, `jira-task-review/SKILL.md`, `jira-task-pr/SKILL.md`의 template 참조 라인을 `"산출물 작성 전 반드시 Read tool로 templates/X.template.md를 읽고 contract를 따른다"`로 통일
3. **5개 SKILL.md 인라인 섹션 지시 제거**: template 파일이 SSOT(Single Source of Truth)이므로 SKILL.md에 박혀있던 섹션 정의 markdown 블록 삭제
4. **plugin.json version bump**: 변경에 맞춰 patch 증가

### Out of Scope

- `scripts/check-template-usage.sh` lint 자동화 — MAE-131과 같은 함정. 수동 점검으로 충분 (skip 결정)
- "plan은 별도 패러다임 유지" 옵션 — 일관성 갭이 외부 리뷰에서 지적된 만큼 통일 방향으로 결정
- 기존 `docs/plan/*.plan.md` 산출물 retroactive 마이그레이션 — 신규 산출물부터 적용

## Acceptance Criteria

### AC-1: plan.template.md contract 적용

- Given: `templates/plan.template.md`가 옛 형식
- When: 본 작업 완료
- Then: 파일 상단에 `<!-- Section contract: ... -->` 블록과 옵셔널 마커 규약 설명이 포함되어 있고, 섹션별로 필수/권장/옵셔널 분류가 명시되어 있다

### AC-2: 옵셔널 섹션 마커

- Given: plan.template.md에 옵셔널로 분류될 섹션이 존재
- When: 통일 작업 완료
- Then: 각 옵셔널 섹션 헤더 직전에 `<!-- optional: <조건/사유> -->` 마커가 부착되어 있다

### AC-3: 5개 SKILL.md 참조 라인 통일

- Given: 5개 SKILL.md가 template을 다양한 방식으로 참조
- When: 본 작업 완료
- Then: 모든 SKILL.md에 `"산출물 작성 전 반드시 Read tool로 templates/X.template.md를 읽고 contract를 따른다"` 형태의 통일된 참조 라인이 존재한다

### AC-4: 인라인 섹션 정의 제거

- Given: 일부 SKILL.md에 섹션 구조가 인라인으로 박혀있음
- When: 본 작업 완료
- Then: SKILL.md에서 template과 중복되는 섹션 정의 블록이 제거되어 있다 (template이 SSOT)

### AC-5: plugin.json version bump

- Given: `.claude-plugin/plugin.json`의 현재 version
- When: 본 작업 완료
- Then: version이 patch 단위로 증가되어 있다

## Risks

| Risk | Impact | Mitigation |
|------|--------|------------|
| 섹션 분류 결정 (어느 것이 필수/옵셔널인지) 주관적 | Medium | design 단계에서 분류 근거를 명문화. design.template.md 분류와 비교하여 일관성 유지 |
| SKILL.md 인라인 섹션 정의 제거 시 의도된 컨텍스트 정보가 함께 사라질 위험 | Medium | "template과 중복되는 부분"만 제거, 스킬 고유의 워크플로 지시는 유지 |
| 기존에 plan.template.md의 옛 형식에 의존하는 자동화/스크립트 존재 가능성 | Low | grep으로 `plan.template.md` 참조처 사전 점검 |
| 5개 SKILL.md 동시 수정 시 일관성 누락 | Low | 모든 변경을 단일 패턴으로 일괄 적용. 검증 단계에서 grep으로 cross-check |

## Edge Cases

- **plan.template.md의 모든 섹션이 "필수"로 분류될 가능성**: Background, Scope, Acceptance Criteria, Task Breakdown은 분명 필수. Risks/Edge Cases는 케이스에 따라 옵셔널일 수 있음 → 옵셔널 마커 후보
- **SKILL.md에 "Step N: Generate ... Document" 섹션이 template 구조를 그대로 반복하는 경우**: 이런 인라인 정의는 제거 대상
- **이미 작성된 기존 plan 문서들**: 마이그레이션 불필요 (Out of Scope). 신규 작성부터 contract 적용
- **plan.template.md에 design.template.md에는 없는 고유 섹션(Task Breakdown 등)**: design 분류와 무관하게 plan 컨텍스트에 맞춰 자체 분류
