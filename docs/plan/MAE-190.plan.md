## Scope Decisions

- **F-002 처리 방식**: "표식 추가"(option 1)를 채택. 사유: best-effort 적재 정신 유지하며 후속 분석 단계에서 필터 가능. "append 거부"는 사용자 워크플로 차단 위험.
- **F-004 처리 방식**: README 명시(option c) 채택. 사유: 동작이 이미 안전(더 많이 redact); 코드 변경은 회귀 위험 대비 가치가 낮음.
- **timestamp 처리 범위**: append 측만 수정. 분석 스크립트는 기존 naive→UTC 가정 로직 유지(이중 변경 회피).
- **단일 PR 정책**: 5개 항목 모두 동일 SKILL.md/README 영역이라 1 PR로 묶음 (Jira 예상 규모와 일치).
- *구현 방식 세부(예: redact import try/except 구조, git rev-parse 실패 시 분기)는 design 단계에서 결정.*
