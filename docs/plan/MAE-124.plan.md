# Plan: MAE-124 - [1.2.3] Bypass 메커니즘 (env + context flag)

## Background

MAE-123(`hooks/scripts/phase-gate.js`)에서 phase gate가 도입되어 워크플로 단계 의존성을 강제한다. 그러나 다음 상황에서는 게이트를 우회할 필요가 있다:

- 디버깅: 특정 단계 산출물이 깨진 상태에서 후속 단계 동작을 확인하고 싶을 때
- 예외 케이스: 외부에서 산출물을 가져온 경우, 또는 일부 단계를 의도적으로 건너뛰는 워크플로
- 마이그레이션: 기존 컨텍스트(`completedSteps` 미기록)가 있는 태스크에서 새 단계를 시도할 때

`phase-gate.js:129`에 이미 "우회: 환경변수 JIRA_PHASE_GATE_BYPASS=1 (MAE-124에서 도입 예정)" 안내가 박혀 있다. 본 작업은 이 우회 메커니즘을 실제로 구현한다.

## Scope

### In Scope
- `phase-gate.js`에 두 가지 우회 채널 추가:
  - 환경변수 `JIRA_PHASE_GATE_BYPASS` (값이 truthy일 때 1회성 우회)
  - `.jira-context.json`의 `bypassGate: true` (영속적 우회, 명시적 opt-in)
- 우회 발동 시 stderr에 명확한 경고 메시지 출력 (사용자/로그가 우회 사실을 인지)
- 단위 테스트: 두 채널 각각, 그리고 정상 차단 케이스가 그대로 동작하는지 검증

### Out of Scope
- 우회 로그를 별도 파일에 기록 (stderr만 사용)
- 우회 권한 제어 (모든 사용자가 사용 가능)
- 다른 hook(PostToolUse 등)으로의 확장
- `bypassGate`를 자동 해제하는 TTL 로직

## Acceptance Criteria

### AC-1: 환경변수 우회
- Given: `completedSteps`가 부족한 컨텍스트에서 `jira-task-design` 진입을 시도
- When: `JIRA_PHASE_GATE_BYPASS=1` 환경변수가 설정된 상태로 hook 실행
- Then: hook은 exit 0으로 통과시키고, stderr에 "⚠️ phase gate bypassed (env)" 형태의 경고를 출력한다

### AC-2: Context flag 우회
- Given: `completedSteps`가 부족하지만 `.jira-context.json`에 `"bypassGate": true`가 있는 상태
- When: hook 실행
- Then: hook은 exit 0으로 통과시키고, stderr에 "⚠️ phase gate bypassed (context flag)" 형태의 경고를 출력한다

### AC-3: 정상 차단 케이스 회귀
- Given: 두 우회 채널 모두 비활성, 선행 단계 누락
- When: hook 실행
- Then: 기존 동작 그대로 exit 2 + permission deny 페이로드 출력 (회귀 없음)

### AC-4: 우선순위 / 빈 값 처리
- Given: `JIRA_PHASE_GATE_BYPASS`가 빈 문자열 또는 `"0"`, `"false"`인 경우
- When: hook 실행
- Then: 우회로 간주하지 않고 정상 검증 흐름을 따른다

## Risks

| Risk | Impact | Mitigation |
|------|--------|------------|
| Bypass가 너무 쉬워 사용자가 게이트 의도를 무시 | 워크플로 품질 저하 | stderr 경고를 눈에 띄게(이모지 + 채널 명시), context flag는 명시적 opt-in |
| 빈 문자열/`"0"` 등 falsy 값 오인 처리 | 의도치 않은 우회 또는 차단 | AC-4 케이스를 테스트로 못박기 |
| `context.bypassGate`가 다른 스킬에서 의도치 않게 set됨 | 영구 bypass 상태 진입 | `bypassGate`는 사용자가 직접 set하는 필드로 문서화, 다른 스킬에서 자동 추가 금지 |
| MAE-126(hooks.json 등록) 미구현 시 본 변경의 효과 미관측 | 통합 테스트 어려움 | 본 태스크는 unit test에 집중, 통합은 MAE-126이 담당 |

## Edge Cases

- **`JIRA_PHASE_GATE_BYPASS`가 공백 문자열 `" "`**: trim 후 빈 문자열로 처리하여 우회 비활성
- **`bypassGate: "true"` (문자열)**: `=== true` 엄격 비교를 사용하므로 우회 비활성 (boolean만 인정, 사용자 실수 방지)
- **`bypassGate: false`**: 명시적 false도 비활성으로 처리
- **두 채널 모두 활성**: 한 번만 경고 출력 (env 우선)
- **컨텍스트 파일이 없을 때**: 기존 fail-open 흐름(exit 0) 유지 — bypass 체크 진입 전에 이미 통과
