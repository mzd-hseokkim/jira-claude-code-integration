# Plan: MAE-171 - [1.1.12] requirements.template.md placeholder 강화 + fallback 동기화

## Background

MAE-117(1.1.4)에서 `templates/requirements.template.md`를 분리할 때는 fallback과 byte-level 1:1 매칭(AC-2) 유지가 우선이었기 때문에 placeholder가 형식만 잡혀 있고 채움 가이드가 약하다. 이후 1.1.10(MAE-169)에서 trace marker가 도입되며 Inline Fallback에는 marker 예시가 추가됐지만, `templates/requirements.template.md`는 갱신되지 않아 **두 파일이 이미 byte-level 일치하지 않는 상태**다 (FR/Edge Cases/Out of Scope/Open Questions 섹션 차이 확인).

본 작업은 다음 3가지 placeholder 강화와 함께 **두 파일을 다시 byte-level 1:1 매칭 상태로 복원**한다:

1. **Goals 측정 sub-template**: `<지표명> · <현재값> → <목표값> · <측정방법>` 형식 강제
2. **FR trace 필드**: `1. <Req-1> *(source: Q<N>, code: <path>:<line>)*` (1.1.10에서 결정한 trace marker 형식 사용)
3. **Open Questions 우선순위 마커**: `- [P1] <Q>` (P1: 다음 단계 차단, P2: 확인 필요, P3: 참고)

블로커 MAE-169(1.1.10)는 완료되어 trace marker 형식이 확정됐으므로 즉시 착수 가능.

## Scope

### In Scope
- `templates/requirements.template.md`의 Goals & Success Criteria placeholder에 측정 sub-template 추가
- `templates/requirements.template.md`의 Functional Requirements 항목에 trace 필드 형식 명시 (1.1.10 marker 형식 일치)
- `templates/requirements.template.md`의 Open Questions에 P1/P2/P3 우선순위 마커 추가
- `templates/requirements.template.md`의 Edge Cases / Out of Scope 항목에도 trace marker 예시 동기화 (Inline Fallback과 일치시키기 위함)
- `skills/jira-task-discover/SKILL.md` Inline Fallback Template (현재 L394-459) 동일 갱신
- `diff` exit 0 검증

### Out of Scope
- 새 placeholder 형식 결정 — 1.1.10이 결정 완료
- discover 워크플로 변경 — 1.1.9(MAE-168) / 1.1.10(MAE-169) / 1.1.11(MAE-170) 범위
- discover Step 4의 marker 부여 로직 — 이미 1.1.10에서 구현됨
- Confirm Gate(Step 4.5) 변경 — 1.1.9 범위

## Acceptance Criteria

### AC-1: Goals 측정 sub-template 적용
- Given: `templates/requirements.template.md`을 연다
- When: Goals & Success Criteria 섹션을 본다
- Then: `<지표명> · <현재값> → <목표값> · <측정방법>` 형식의 예시가 placeholder로 명시되어 있다

### AC-2: FR trace 필드 적용
- Given: `templates/requirements.template.md`을 연다
- When: Functional Requirements 섹션을 본다
- Then: 각 항목 끝에 trace marker 형식(`*(source: Q<N>, code: <path>:<line>)*` 등) 예시가 1.1.10(MAE-169)에서 결정한 형식과 일치하게 표기되어 있다

### AC-3: Open Questions 우선순위 마커 적용
- Given: `templates/requirements.template.md`을 연다
- When: Open Questions 섹션을 본다
- Then: `- [P1] <Q>` 형식과 P1/P2/P3 의미(다음 단계 차단 / 확인 필요 / 참고) 설명이 명시되어 있다

### AC-4: Inline Fallback Template 동기화
- Given: `skills/jira-task-discover/SKILL.md`의 Inline Fallback Template 섹션을 연다
- When: `templates/requirements.template.md`과 비교한다
- Then: AC-1, AC-2, AC-3의 강화된 placeholder가 동일하게 반영되어 있다

### AC-5: Byte-level 1:1 매칭 (MAE-117 AC-2 복원)
- Given: 작업 완료 후
- When: `diff <(sed -n '<범위>p' skills/jira-task-discover/SKILL.md) templates/requirements.template.md` 실행
- Then: exit code 0 (차이 없음)

### AC-6: 기존 호환성 유지
- Given: 작업 완료 후
- When: discover 워크플로 분기(default/--lite/--from/--lite+--from)를 검토한다
- Then: MAE-117 AC-3(섹션 호환성) 및 AC-4(`--lite` 안내 주석)가 유지되어 있다

## Edge Cases

- **`--lite` 모드**: Goals 측정 sub-template은 1줄 형식이라 5줄 제한 내 수용 가능. NFR placeholder는 기존 "N/A — lite mode" 안내 유지.
- **`--from` 모드**: import 본문에 marker가 없을 수 있음. placeholder 예시는 default 케이스 기준으로 작성하되, `--from` 변형(`*(source: from)*` 등)은 SKILL.md L245-254에 이미 명시되어 있으므로 placeholder에 반복 표기 불필요.
- **Open Questions에 [CONFLICT] 항목**: P1/P2/P3 우선순위 마커는 일반 TBD 항목용. [CONFLICT] 항목은 prefix가 출처 표시 역할이라 우선순위 마커 부착 여부는 별도 결정 필요 — 본 작업에서는 [CONFLICT] 예시는 그대로 두고 일반 TBD 항목에만 우선순위 마커 예시 추가.
- **기존 byte-level 매칭이 이미 깨진 상태**: MAE-117 AC-2가 1.1.10 시점부터 deviation됨. 본 작업으로 다시 동기화하면 AC-2 복원.
