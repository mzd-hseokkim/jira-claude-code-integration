# Plan: MAE-118 - [1.1.5] completedSteps에 "discover" 추가

## Background

`.jira-context.json`의 `completedSteps` 배열에는 워크플로의 각 단계가 누적된다. MAE-104 (Phase 1.1)에서 새롭게 도입된 `discover` 단계 (MAE-115에서 스킬 작성 완료)는 워크플로에 정식으로 합류했지만, 현재 다음 위치에서는 `discover`가 "유효 단계"로 인식되지 않는다.

- `CLAUDE.md`의 "Workflow Progress Tracking" 섹션 — 유효한 단계 목록(line 177)
- `hooks/scripts/session-start.js` — `steps` 배열 / `nextStepMap` (lines 89, 104, 131-134)
- `commands/jira-task.md` — 워크플로 단계 순서 안내(line 139)

이로 인해 `discover` 단계를 마친 후 `.jira-context.json`에 `"discover"`를 기록하더라도 세션 시작 훅이나 다음 단계 추천 로직이 이를 워크플로의 일부로 인식하지 못한다. 본 서브태스크의 목적은 이 인식 불일치를 해소하는 것이다.

확정된 워크플로(MAE-104 기준):
```
discover → create → init → start → plan → design → impl → test → review → merge → pr → done
```

## Scope

### In Scope
- `CLAUDE.md` "Workflow Progress Tracking" 섹션의 유효 단계 목록에 `discover` 추가
- `hooks/scripts/session-start.js`의 `steps` 배열에 `discover` 추가 (Progress 라인 렌더링용)
- `hooks/scripts/session-start.js`의 `nextStepMap`에 `discover: 'create'` 매핑 추가
- `hooks/scripts/session-start.js`의 Available commands 안내 문자열에 `discover` 액션 노출 (가독성)
- `commands/jira-task.md`의 워크플로 단계 순서 안내(line 139) 갱신 — `discover` 포함
- `discover`는 신규 단계 순서상 **`create` 이전**에 위치 (MAE-104 ADR — 옵션 A)
- `.claude-plugin/plugin.json`의 `version` 증가

### Out of Scope
- `commands/jira-task.md`의 라우팅 로직(action 분기)에 `discover` 추가 — **MAE-119**의 책임
- `jira-task-discover` 스킬 작성 — MAE-115에서 완료
- `templates/requirements.template.md` — MAE-117에서 완료
- `discover --from-requirements`로 `create` 연동 — MAE-116
- README/CLAUDE.md 다이어그램 갱신 (워크플로 그래프) — MAE-120 / MAE-121
- 기존 `.jira-context.json` 마이그레이션 — 신규 단계는 누적형이므로 마이그레이션 불필요
- `jira-task-auto`의 자동 실행 시퀀스에 `discover` 포함 — auto는 `start → plan → … → review`만 다룸 (현 정책 유지)

## Acceptance Criteria

### AC-1: 유효 단계 목록에 discover 포함
- Given: `CLAUDE.md`의 "Workflow Progress Tracking" 섹션을 읽는다
- When: 유효한 단계 목록을 확인한다
- Then: `discover`가 `create` 또는 `init`보다 앞 순서로 명시되어 있고, 기존 단계 (`init`, `start`, `plan`, `design`, `impl`, `test`, `review`, `merge`, `pr`, `done`) 가 모두 유지된다

### AC-2: session-start 훅이 discover를 단계로 렌더링
- Given: `.jira-context.json`의 `completedSteps`에 `"discover"`가 포함되어 있다
- When: 세션 시작 훅이 실행되어 Progress 라인을 출력한다
- Then: Progress 출력에 `discover ✓ → ...` 형태로 `discover` 단계가 가시화된다

### AC-3: discover 다음 단계 안내
- Given: `completedSteps`의 마지막 워크플로 단계가 `"discover"`이다
- When: session-start 훅의 `nextStepMap` 로직이 다음 단계를 추천한다
- Then: `Next step: /jira-task create <TASK-ID>` 형태로 `create`가 추천된다

### AC-4: 기존 단계와 충돌 없음
- Given: `completedSteps`가 기존 형식(`["init", "start", "plan"]` 등)으로만 채워진다
- When: 변경된 코드와 문서가 실행/렌더링된다
- Then: 기존 Progress 출력 / 다음 단계 추천 / 유효 단계 검증이 모두 정상 동작 (회귀 없음)

### AC-5: commands 문서 갱신
- Given: `commands/jira-task.md`의 "워크플로 단계 순서" 안내 라인을 확인한다
- When: 라인 내용을 읽는다
- Then: 단계 순서가 `discover → create → init → start → plan → design → impl → test → review → merge → pr → done`로 표기되어 있다

### AC-6: 플러그인 버전 증가
- Given: 본 서브태스크에 플러그인 코드/스킬/문서 변경이 포함되어 있다
- When: `.claude-plugin/plugin.json`을 확인한다
- Then: `version`이 직전 릴리스(0.13.1)보다 한 단계 이상 증가되어 있다

## Edge Cases

- **기존 `.jira-context.json`에 `completedSteps: ["init", "start", ...]`만 있는 경우**: 변경 후에도 Progress는 `discover → init ✓ → start ✓ → ...` 식으로 정상 출력. `discover`는 ✓ 없이 표기 — 사용자가 수동으로 건너뛴 케이스로 인식.
- **`completedSteps`에 `["discover"]`만 있고 `init`이 없는 경우**: 다음 단계 안내가 `create`를 가리킴. 그러나 `create`는 워크플로 명령(`/jira-task create`)이 존재하므로 정상 흐름.
- **`completedSteps`에 워크플로 외 임의 문자열이 섞여 있는 경우**: `[...completed].reverse().find(s => steps.includes(s))` 로직에 의해 무시되며 회귀 없음.
- **`completedSteps`에 `"create"`만 있는 경우**: 본 서브태스크에서 `create: 'init'` 매핑을 함께 추가하면 다음 단계로 `init`이 추천되어 흐름 연속성 확보.
- **`discover` 단계만 있고 `create`/`init` 등 후속 단계가 없는 신규 워크플로 시나리오**: session-start의 docsFound 탐지가 `Plan/Design/Test/Review`만 보므로 `requirements` 문서 가시화는 본 작업 범위 외(후속 개선 후보).
- **`jira-task-discover` 스킬이 `.jira-context.json`을 갱신하지 않는 정책**: 본 PR 범위에서는 "유효 단계 등록"만 처리. 자동 기록 정책은 별도 결정 — Risks 항목으로 명시.
