## Background

`jira-task-discover` 스킬(MAE-115)은 Step 4에서 요구사항 문서를 생성할 때 다음 우선순위로 템플릿을 선택한다:

1. `templates/requirements.template.md`이 존재하면 그것을 베이스로 사용
2. 없으면 SKILL.md의 **Inline Fallback Template** 섹션 구조를 사용

현재 1번 파일이 없어 모든 discover 호출이 fallback 분기로만 동작한다. 정식 템플릿 파일을 작성해 이 봉합을 풀고, discover 스킬이 의도된 정식 경로로 동작하도록 한다.

또한 본 템플릿은 향후 MAE-106(Phase 1.3) 정비 작업과 일관된 형식 기반을 제공해야 한다 (각 단계별 template이 강제 형식 contract로 동작).

## Acceptance Criteria

### AC-1: 파일 생성 및 위치

- **Given**: 레포 루트에서 `templates/` 디렉터리가 존재한다
- **When**: 본 태스크 구현이 완료된다
- **Then**: `templates/requirements.template.md` 파일이 존재하고, 마크다운 형식이며, 비어 있지 않다

### AC-2: 섹션 구조 호환성

- **Given**: discover SKILL.md의 `## Inline Fallback Template` 섹션이 정의한 구조
- **When**: `templates/requirements.template.md`을 읽어 비교한다
- **Then**: 다음 섹션이 모두 존재하고 순서가 동일하다:
  - 메타 헤더(`Slug`, `Mode`, `Generated At`, `Source`)
  - `Stakeholders`, `Goals & Success Criteria`, `Constraints`, `Non-functional Requirements`
  - `Codebase Context`, `Functional Requirements`
  - `Edge Cases`, `Out of Scope`, `Open Questions`
  - `Proposed Issue Breakdown`

### AC-3: discover 스킬과의 동작 호환

- **Given**: `templates/requirements.template.md`이 존재하는 상태
- **When**: discover 스킬 Step 4가 호출된다 (실 호출 또는 코드 리뷰로 검증)
- **Then**: 스킬은 fallback 분기 대신 정식 템플릿을 베이스로 사용한다 (스킬 코드의 분기 로직은 변경하지 않음 — 파일 존재 여부만으로 동작 분기됨)

### AC-4: --lite 모드 표기

- **Given**: 템플릿이 default/lite 모드 모두를 지원해야 한다
- **When**: 템플릿을 읽는다
- **Then**: `Edge Cases`와 `Out of Scope` 섹션에 "`--lite` 모드에서는 이 섹션 생략" 안내가 마크다운 주석 또는 명시 문구로 포함된다

### AC-5: Phase 1.3 일관성

- **Given**: MAE-106이 정의할 template 형식 표준
- **When**: 본 템플릿을 다른 기존 템플릿(`plan.template.md`, `report.template.md`)과 비교한다
- **Then**: heading level, 플레이스홀더 표기(`<...>` 또는 `{...}`), 메타 헤더 위치 등이 일관된다

## Edge Cases

- **빈 템플릿 파일**: 파일은 존재하나 본문이 없는 경우 → discover 스킬이 빈 본문을 베이스로 fallback하지 않고 그대로 사용해 빈 문서를 생성할 위험. 파일에 최소 모든 섹션 헤딩은 포함되어야 함
- **메타 헤더 placeholder 미해석**: `<slug>` 같은 자리표시자가 그대로 산출 문서에 남는 경우 → discover 스킬 책임 영역. 본 태스크는 placeholder 표기 일관성만 보장
- **`--lite` 모드 처리**: 템플릿 파일 자체는 모든 섹션을 포함. `--lite` 시 어떤 섹션을 생략할지는 discover 스킬이 판단 (본 템플릿은 안내 주석으로 신호만 제공)
- **`--from` 모드와의 상호작용**: `--from <기존문서>`로 import한 베이스가 본 템플릿 구조와 다를 수 있음 → discover Step 4가 보강(merge) 처리. 본 태스크 영향 없음
- **개행/공백**: 마크다운 렌더링 호환을 위해 섹션 간 빈 줄 1개, 파일 끝 개행 포함

## Implementation Strategy

본 태스크는 단일 마크다운 파일 작성이며 코드 변경이 없다. 따라서 design 단계는 **경량(lightweight)** 으로 진행해도 무방하며, plan에서 design 본문 일부를 흡수하여 바로 impl로 진입 가능하다.

권장 흐름: `plan ✓ → (경량) design → impl → test → review → merge → done`

- **design 경량화**: 섹션 매핑표와 형식 결정만 담음
- **impl**: 단일 Write 호출
- **test**: discover 스킬 Step 4 분기 동작 수동 검증 (실 호출 또는 코드 리뷰). E2E 테스트는 불필요
