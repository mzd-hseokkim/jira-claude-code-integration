# Plan: MAE-122 - [1.2.1] Phase 의존 그래프 정의 + 외부화

## Background

상위 Phase 1.2 (MAE-105)는 PreToolUse hook 기반의 phase gate를 도입해 "design 없이 impl 진입", "test 통과 없이 PR 생성" 같은 워크플로 위반을 코드 레벨에서 차단하는 것을 목표로 한다.

본 작업(MAE-122)은 그 첫 단추로 phase 의존 그래프를 정의하고 `hooks/scripts/phase-gate.config.json`으로 외부화한다. 후속 MAE-123(`phase-gate.js`)이 이 config를 읽어 동작하므로 **블로킹 선행 작업**이다.

회사별/프로젝트별로 워크플로 단계 요구사항이 다를 수 있으므로 코드가 아닌 JSON config로 분리하여 커스터마이즈 여지를 확보한다.

## Scope

### In Scope
- `hooks/scripts/phase-gate.config.json` 신규 작성
- `discover → create → init → start → plan → design → impl → test → review → merge → pr → done` 전 단계의 선행 조건 명시
- 각 단계별 요구 산출물(예: design은 `docs/design/<TASK-ID>.design.md` 파일 + `completedSteps`에 `"design"` 포함) 명시
- 커스터마이즈 가이드 한 줄 추가 (config 상단 주석 또는 별도 문서)
- 후속 MAE-123이 config를 단순 import해서 쓸 수 있도록 명확한 스키마 설계

### Out of Scope
- `phase-gate.js` 구현 (MAE-123)
- `hooks/hooks.json` PreToolUse 등록 (MAE-105의 후행 sub-task)
- Bypass 메커니즘 (별도 sub-task)
- 테스트 시나리오 (별도 sub-task)
- README의 "Phase Gate" 섹션 (별도 sub-task)

## Acceptance Criteria

### AC-1: Config 파일 존재 및 유효성
- Given: `hooks/scripts/phase-gate.config.json` 경로
- When: Node.js로 `require()` 또는 `JSON.parse()`로 로드
- Then: 파싱 에러 없이 객체로 로드된다

### AC-2: 모든 워크플로 단계의 선행 조건 명시
- Given: `/jira-task` 워크플로의 12단계 (discover, create, init, start, plan, design, impl, test, review, merge, pr, done)
- When: config의 `phases` 키를 조회
- Then: 모든 단계가 키로 존재하며 각 단계에 `requires` (선행 단계 배열)와 필요 시 `artifacts` (요구 파일 패턴) 필드가 정의되어 있다

### AC-3: 의존 그래프가 이슈 description의 Phase Dependencies와 일치
- Given: MAE-122 이슈 description의 Phase Dependencies 정의
- When: config의 각 단계 `requires`를 비교
- Then: plan→start, design→plan, impl→design, test→impl, review→test, merge→review 등 일치한다

### AC-4: 커스터마이즈 가이드 명시
- Given: 사용자가 회사 워크플로에 맞춰 customize하려는 상황
- When: config 파일 또는 관련 문서를 열어본다
- Then: "복사해서 수정하라"는 한 줄 가이드와 수정 예시가 보인다

## Risks

| Risk | Impact | Mitigation |
|------|--------|------------|
| 스키마가 너무 단순해 MAE-123에서 확장 필요 | 중 (재작업 발생) | design 단계에서 MAE-123 사용 시나리오를 미리 검토하여 `artifacts.glob`, `artifacts.completedStep` 등 필드 사전 포함 |
| JSON에 주석을 못 쓰는데 가이드를 어디에 둘지 모호 | 저 | `_comment` / `_meta` 키로 메타데이터 포함 (관례적 패턴) |
| 워크플로 단계 일부(예: discover, create)는 init 이전이라 phase gate 대상 아님 | 저 | config에 `enforced: true/false` 플래그로 구분 |
| 의존 그래프와 실제 스킬 동작 불일치 | 중 | 스킬 SKILL.md를 직접 확인하여 completedSteps 패턴 검증 |

## Edge Cases

- **선택적 단계**: `discover`, `create`는 일부 작업에서만 발생 → `requires: []` + `enforced: false`로 처리
- **병렬 가능 단계**: 현재는 모두 선형. 향후 변경 대비 `requires`는 배열로 유지 (단일 선행 단계도 `["start"]` 형식)
- **`merge`와 `pr`의 순서**: 현재 워크플로상 merge → pr (로컬 병합 후 PR). config에 동일 순서 반영
- **`bypassGate` 필드**: MAE-122 범위는 아니지만, MAE-123에서 사용될 것이므로 스키마 차원에서 충돌 없도록 `bypassable: true` 같은 메타필드 미리 고려 (실제 추가는 design에서 결정)
- **워크트리에서 `.jira-context.json` 위치**: config 자체는 무관. 이 이슈가 아닌 MAE-123의 책임이지만 스키마가 그 사용을 막지 않도록 단순하게 유지
