# Plan: MAE-120 - [1.1.7] CLAUDE.md PDCA 문서 목록 + 워크플로 그래프 갱신

## Background

`/jira-task discover` 액션 도입(MAE-115~119)으로 PDCA 산출물에 Requirements 문서가 추가되었고, 워크플로의 진입 단계에 `discover`가 들어왔다. 하지만 프로젝트 루트의 `CLAUDE.md`에는 이 변경사항이 반영되어 있지 않다. 신규 사용자/세션이 CLAUDE.md만 보고도 전체 워크플로를 이해할 수 있도록 문서를 동기화한다.

## Scope

### In Scope
- `CLAUDE.md` "PDCA Documents" 섹션에 Requirements 항목 추가
- `CLAUDE.md` "Workflow Commands" 섹션에 `/jira-task discover` 항목 추가
- 워크플로 그래프 또는 단계 순서 표기에 `discover → create → init → ...` 반영
- `.claude-plugin/plugin.json` version bump

### Out of Scope
- 다른 스킬/문서/템플릿 수정 (이미 MAE-115~119에서 완료)
- README 갱신 (별도 이슈)
- 워크플로 자체 변경

## Acceptance Criteria

### AC-1: PDCA 문서 목록에 Requirements 추가
- Given: `CLAUDE.md`의 "PDCA Documents" 섹션
- When: 문서를 읽음
- Then: `Requirements: docs/requirements/<slug>.requirements.md` 항목이 Plan/Design/Test Report와 함께 나열된다

### AC-2: Workflow Commands 목록에 discover 추가
- Given: `CLAUDE.md`의 "Workflow Commands" 섹션
- When: 명령어 목록을 확인
- Then: `/jira-task discover [주제]` 항목이 `init` 위(또는 워크플로 순서상 적절한 위치)에 포함된다

### AC-3: 워크플로 단계 순서에 discover 반영
- Given: `CLAUDE.md`의 Workflow Progress Tracking 또는 워크플로 순서 표기
- When: 단계 순서를 확인
- Then: `discover → create → init → start → plan → design → impl → test → review → merge → pr → done` 순서가 반영되어 있다 (이미 일부 반영되어 있으면 OK)

## Risks

| Risk | Impact | Mitigation |
|------|--------|------------|
| Workflow Progress Tracking의 "유효한 단계" 리스트는 이미 `discover` 포함 — 중복 작업 가능성 | 낮음 | 현재 상태 확인 후 누락된 부분만 수정 (Surgical Changes) |
| 다른 섹션에서 "PDCA Documents", "Workflow Commands"를 재참조하는 경우 | 낮음 | grep로 다른 위치 사용 여부 확인 |

## Edge Cases

- "유효한 단계" 목록(line 194)에는 이미 `discover`, `create`가 포함되어 있다 — PDCA Documents/Workflow Commands 섹션만 정확히 보강
- 워크플로 그래프가 별도 다이어그램이 아닌 텍스트 단계 순서로만 표현되어 있다면 line 194의 단계 순서 라인이 그래프 역할을 한다
