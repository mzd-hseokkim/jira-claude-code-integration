# Plan: MAE-115 — [1.1.2] jira-task-discover 스킬 작성

## Background

`jira-task-discover`는 부모 에픽 MAE-104(Phase 1.1)에서 도입하기로 한 신규 스킬이다.
현재 워크플로는 `create → init → start → plan → ...`으로, "Jira 이슈를 자연어로 등록"까지만 자동화되어 있다. 그 앞에 있어야 할 **discovery → 요구사항 문서 → 이슈 분해** 흐름이 비어 있다.

`discover`는 애매모호한 자연어 주제를 입력받아, 코드베이스 탐색과 사용자 질문을 거쳐 **명시적인 요구사항 분석서**를 생성하는 단계다. 산출물은 다음 단계인 `jira-task-create`(MAE-116에서 `--from-requirements` 옵션 추가)로 연결된다.

본 태스크는 SKILL.md 작성에만 집중한다. 템플릿 파일 생성(MAE-117), `create` 연결(MAE-116), `completedSteps` 확장(MAE-118), 라우팅 추가(MAE-119), 문서 갱신(MAE-120, MAE-121)은 형제 서브태스크로 분리되어 있다.

## Scope

### In Scope

- `skills/jira-task-discover/SKILL.md` 신규 작성
- 4단계 워크플로 구현: 컨텍스트 수집 → 배치 질문 → 요구사항 문서 생성 → 이슈 분해 제안
- `--lite` 모드 (질문 3개 이하, 한 페이지 문서)
- `--from <파일경로>` 모드 (기존 요구사항 문서 import)
- 자연어 주제로부터 영문 kebab-case 슬러그 자동 생성 + 사용자 confirm 1회
- 코드베이스 탐색 휴리스틱: 키워드 3-5개 추출 → Glob/Grep → 상위 10개 파일 발췌
- 산출물: `docs/requirements/<TOPIC-SLUG>.requirements.md` (이슈 분해 제안 섹션 포함)
- 템플릿 부재 시 인라인 fallback 구조

### Out of Scope

- `templates/requirements.template.md` 실제 생성 → MAE-117
- `jira-task-create`와의 import 연결 (`--from-requirements`) → MAE-116
- `completedSteps`에 `"discover"` 추가 → MAE-118
- `commands/jira-task.md`에 `discover` 액션 라우팅 → MAE-119
- CLAUDE.md PDCA 문서 목록 갱신 → MAE-120
- README 워크플로 다이어그램 갱신 → MAE-121
- Jira 이슈 코멘트/첨부 (discover는 로컬 문서 단계로 한정)
- 실제 Jira 이슈 생성 (그건 `create` 단계의 책임)
- 인덱스 파일 (`docs/requirements/INDEX.md` 등) 자동 관리

## Acceptance Criteria

### AC-1: 4단계 워크플로 모두 구현됨

- Given: `skills/jira-task-discover/SKILL.md` 작성됨
- When: 사용자가 `/jira-task discover "사용자 알림 시스템"` 실행
- Then: SKILL.md가 (1) 키워드 추출 후 코드베이스 탐색, (2) AskUserQuestion으로 4건 질문 배치, (3) `docs/requirements/<slug>.requirements.md` 생성, (4) 문서 안에 에픽/스토리/서브태스크 분해 섹션을 포함하도록 명시되어야 한다

### AC-2: --lite 모드 동작 명세

- Given: SKILL.md 작성됨
- When: `--lite` 플래그 사용
- Then: 질문 3개 이하, 한 페이지 분량의 축약된 요구사항 문서를 생성하도록 명시. 질문 4개 묶음 중 "비기능 요구사항"이 기본 제외

### AC-3: --from 모드 동작 명세

- Given: SKILL.md 작성됨
- When: `--from <기존-요구사항-파일.md>` 사용
- Then: Step 1.5(코드베이스 탐색)와 Step 2(질문 배치)는 보강용으로만 사용하고, 기존 문서 내용을 베이스로 출력 문서 생성하도록 명시

### AC-4: 슬러그 confirm 흐름 명세

- Given: SKILL.md 작성됨
- When: 자연어 주제 입력
- Then: LLM이 영문 kebab-case 슬러그 자동 생성 → AskUserQuestion으로 1회 사용자 확인 → 확정 후 파일명에 사용

### AC-5: 다른 jira-task-* 스킬과 일관된 메타데이터

- Given: SKILL.md 작성됨
- Then: frontmatter에 `name`, `description`(invocation 키워드 한국어/영어 포함), `argument-hint`, `allowed-tools`, `user-invocable: false` 포함. Language Rule 섹션 포함

## Edge Cases

- **자연어 주제 누락**: 인자 없이 호출 시 → 사용자에게 주제 입력 요청
- **`--from` 파일 부재**: 경로 검증 후 에러 메시지 + 종료
- **`--from`과 `--lite` 동시 사용**: 둘 다 적용 (질문 축소 + 기존 문서 import)
- **키워드 추출 결과 0개**: 일반 디렉터리 구조(`ls`)로 폴백
- **Glob/Grep 결과 없음**: "관련 영역 미발견"으로 컨텍스트 섹션에 명시하고 진행
- **슬러그가 이미 존재**: `<slug>-2`, `<slug>-3` 식으로 suffix 부여하거나 사용자에게 재선택 요청
- **사용자가 모든 질문에 "Other → (빈 답)" 응답**: 그대로 문서에 "TBD"로 기록하고 진행
- **이미 동일 주제로 요구사항 문서 존재**: overwrite 여부 사용자 confirm
- **한글 주제에서 영문 슬러그 생성 실패**: LLM이 영문 번역/요약 후 슬러그 생성. 실패 시 사용자 직접 입력
- **코드베이스 탐색 결과가 컨텍스트 폭주**: 파일당 30줄 발췌 상한 + 상위 10개 파일 상한 강제
