## Background

`jira-task-discover` 스킬은 Step 4(Generate Requirements Document)에서 LLM이 합성한 결과(Functional Requirements, Edge Cases, Out of Scope, Open Questions 등)를 **사용자 검증 없이 그대로 Step 5(Issue Breakdown)와 최종 문서로 흘려보낸다**. MAE-117 작업 중 분석 결과 다음 케이스에서 합성 오류가 누적된다:

- 입력이 길고 모순될 때 (대량 대화 로그, 낡은 PRD 등 — 특히 `--from <path>` 모드)
- LLM이 코드에 없는 기능을 Functional Requirements에 hallucinate 했을 때
- Story/Sub-task 분해가 임의 지점에서 끊겼을 때 (Issue Breakdown 트리 결손)

해결책: Step 4와 Step 5 사이에 **합성 결과 confirm gate (Step 4.5)** 를 신설해, 사용자가 한 번 검토·수정·취소할 수 있는 분기점을 제공한다. 단순 입력에서는 "그대로 진행" 한 번이면 끝나므로 마찰이 거의 없고, 복잡 입력에서는 hallucination을 차단할 수 있다.

- **Given**: 현재 SKILL.md는 Step 0 ~ Step 6 + Inline Fallback Template + Error Handling + Non-goals 구조

### AC-2: AskUserQuestion 호출 형식 명시

- **Given**: Step 4.5 섹션
- **When**: 섹션 본문을 읽는다
- **Then**: `AskUserQuestion`을 사용한 confirm 호출 의사코드 또는 예시가 포함되어 있고, 다음 3개 옵션이 명시된다:
  - `그대로 진행` (proceed) → Step 5
  - `수정 요청` (revise) → 자유 입력으로 수정 항목 수신 → LLM 재합성 → 다시 Step 4.5
  - `취소` (cancel) → 문서 생성 중단 + 임시 결과 폐기 + 종료 메시지

### AC-3: 무한 루프 방지 가드

- **Given**: 사용자가 "수정 요청"을 반복 선택할 수 있는 상황

- **Then**: 재합성 최대 횟수 N(예: 3회)이 명시되어 있고, N회 초과 시 동작(예: "강제 confirm" 또는 "취소 권장 안내")이 정의되어 있다

### AC-4: --lite 모드 호환성

### AC-5: 회귀 방지 — 다른 섹션 무결성

## Edge Cases

- **재합성 결과가 직전 결과와 완전히 동일**: LLM이 사용자 수정 요청을 반영하지 못한 경우 → 사용자에게 "변경 없음" 안내 + 카운터는 증가 (무한 회피)
- **사용자가 "수정 요청"의 자유 입력에 빈 문자열 또는 공백만 입력**: 변경 의도 불명 → 직전 합성 결과 그대로 confirm 단계로 복귀 (재합성 X)
- **사용자가 "취소"를 선택하면 임시 산출물(메모리상 합성 결과)은 즉시 폐기**: 파일 시스템에는 아직 쓰지 않았으므로 별도 cleanup 불필요. 단, Step 4가 이미 partial write를 했다면 해당 파일도 unlink (구현 시 Step 4의 파일 쓰기 시점을 Step 4.5 이후로 미루는 것이 가장 깔끔)
- **AskUserQuestion이 비대화형 환경에서 호출 불가**: 본 스킬은 user-invocable=false라 항상 사용자 세션 내에서만 호출됨 → 가정상 발생하지 않으나, 안전장치로 "응답 없음 → `그대로 진행` default 적용" 명시 권장
- **`--from` 모드에서 import 베이스 자체가 충분히 정확해 합성이 거의 불필요한 경우**: 합성 결과를 그대로 표시하더라도 사용자가 즉시 `그대로 진행` 가능 → gate가 1초 이상 마찰을 만들지 않음
- **Functional Requirements가 0개로 합성된 경우**: 모든 답변이 "Other → (빈)"인 극단 케이스 → confirm 단계에서 "합성된 항목이 없습니다. 그대로 진행하면 빈 문서가 생성됩니다" 경고 표시

## Implementation Strategy

본 태스크는 단일 마크다운 파일(`skills/jira-task-discover/SKILL.md`) 수정이며 코드 변경이 없다. design 단계는 **경량(lightweight)** 으로 진행 가능:

- **design 경량화**: Step 4.5의 섹션 구조와 AskUserQuestion 의사코드만 명세
- **impl**: SKILL.md에 Step 4.5 섹션 삽입 + Step 6/Error Handling 보강 (단일 Edit/Write)
- **test**: 수동 시나리오 점검 (정상 confirm, 수정 1회, 수정 N회 초과, 취소). 실제 discover 스킬 호출은 선택. 본 태스크는 SKILL.md 명세 자체가 contract이므로 코드 리뷰 위주
- **review**: 기존 섹션 회귀 없는지 diff 검토 (AC-5 중점)

권장 흐름: `plan ✓ → (경량) design → impl → test → review → merge → done`
