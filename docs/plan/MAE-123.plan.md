# Plan: MAE-123 - [1.2.2] phase-gate.js 작성 (PreToolUse hook)

## Background

상위 Phase 1.2 (MAE-105)는 PreToolUse hook 기반 phase gate를 도입해 워크플로 위반(예: design 없이 impl 진입, test 통과 없이 PR 생성)을 코드 레벨에서 차단한다.

선행 작업 MAE-122에서 의존 그래프(`hooks/scripts/phase-gate.config.json`)가 정의·외부화되었다. 본 작업(MAE-123)은 그 config를 읽어 실제로 게이팅을 수행하는 `phase-gate.js` 스크립트를 작성한다. 이 스크립트는 `Skill` 도구 호출(즉, `jira-task-*` 스킬 호출) 직전에 PreToolUse hook으로 실행되어 선행 phase 미충족 시 호출을 차단하고 사용자에게 안내 메시지를 출력한다.

후속 작업과의 관계:
- MAE-124: bypass 메커니즘(env / context flag) — 본 스크립트가 정의하는 차단 로직에 우회 경로를 덧붙인다
- MAE-125: 테스트 시나리오 — 본 스크립트의 동작을 검증
- MAE-126: `hooks/hooks.json`에 PreToolUse 등록 — 본 스크립트가 실제로 호출되도록 연결
- MAE-127: README 문서화

## Scope

### In Scope
- `hooks/scripts/phase-gate.js` 신규 작성 (Node.js, no external deps)
- PreToolUse hook payload(JSON via stdin) 파싱
- 호출 도구가 `Skill`이고 `skill` 파라미터가 `jira-integration:jira-task-<phase>` 패턴이면 phase 추출
- cwd 기반으로 가까운 `.jira-context.json` 탐색 (worktree 호환: cwd → 부모 디렉토리 순으로 상향 탐색)
- `phase-gate.config.json` 로드 후 `requires`(선행 단계) + `artifacts`(요구 파일) 검증
- 위반 시 stderr에 안내 메시지 + exit code 2 (Claude Code hook 차단 규약)
- 통과 시 exit code 0 (no output)

### Out of Scope
- `hooks/hooks.json`에 PreToolUse hook 등록 (MAE-126)
- bypass 메커니즘 구현 — env (`JIRA_PHASE_GATE_BYPASS=1`) 및 `.jira-context.json`의 `bypassPhaseGate` flag (MAE-124)
- 테스트 케이스 작성 (MAE-125)
- 사용자 문서/README 업데이트 (MAE-127)
- `Skill` 외 다른 도구(Bash, Edit 등)에 대한 게이팅 (현재 범위는 스킬 호출만)

## Acceptance Criteria

### AC-1: 스크립트 파일 존재 및 실행 가능
- Given: `hooks/scripts/phase-gate.js` 경로
- When: `node hooks/scripts/phase-gate.js < /dev/null`로 실행 (빈 입력)
- Then: 크래시 없이 종료되며 (입력이 비어 있으므로 exit 0 또는 graceful no-op 처리), 의존 패키지 없이 동작한다

### AC-2: Skill 호출 인터셉트 + phase 추출
- Given: PreToolUse payload `{ "tool_name": "Skill", "tool_input": { "skill": "jira-integration:jira-task-impl", "args": "MAE-123" } }`이 stdin으로 전달
- When: 스크립트 실행
- Then: phase로 `"impl"`을 추출한다 (이후 검증 단계 진행)

### AC-3: 비-Skill 도구 호출은 통과
- Given: PreToolUse payload `{ "tool_name": "Bash", "tool_input": { "command": "ls" } }`
- When: 스크립트 실행
- Then: 즉시 exit 0 (검증 스킵, no output)

### AC-4: jira-task 외 스킬은 통과
- Given: payload `{ "tool_name": "Skill", "tool_input": { "skill": "review", "args": "" } }`
- When: 스크립트 실행
- Then: 즉시 exit 0 (게이팅 대상 아님)

### AC-5: `.jira-context.json` 탐색 (worktree 호환)
- Given: 현재 작업 디렉토리가 worktree (`.jira-context.json`이 cwd에 존재)
- When: 스크립트 실행
- Then: cwd에서 직접 발견 후 사용. cwd에 없으면 상위 디렉토리로 상향 탐색 (max 6 levels)
- Given: `.jira-context.json` 자체가 존재하지 않음
- When: 스크립트 실행
- Then: gate를 적용할 수 없으므로 exit 0 (graceful skip)

### AC-6: 선행 단계 누락 시 차단
- Given: `.jira-context.json`의 `completedSteps = ["init", "start", "plan"]`이고 호출이 `jira-task-impl`
- When: config의 `phases.impl.requires = ["design"]` 검증
- Then: stderr에 한국어 안내 메시지 출력 + exit code 2 (호출 차단)

### AC-7: 요구 산출물(artifact) 누락 시 차단
- Given: `completedSteps = ["init", "start", "plan", "design"]`이지만 `docs/design/MAE-123.design.md` 파일이 없음, 호출이 `jira-task-impl`
- When: config의 `phases.impl.artifacts = [{ "fileGlob": "docs/design/{TASK_ID}.design.md" }]` 검증 ({TASK_ID}는 `.jira-context.json`의 `taskId`로 치환)
- Then: stderr에 안내 메시지 + exit code 2

### AC-8: 통과 케이스
- Given: 모든 `requires` 충족 + 모든 `artifacts` 존재
- When: 스크립트 실행
- Then: exit 0, no stdout/stderr

### AC-9: `enforced: false` 단계는 게이팅 스킵
- Given: config의 `phases.discover.enforced = false`
- When: `jira-task-discover` 호출
- Then: requires가 비어 있어도 무관하게 통과 (exit 0)

### AC-10: 안내 메시지 가독성
- Given: 위반 발생
- When: stderr 출력 확인
- Then: 한국어 + 다음 정보 포함:
  - 요구되는 phase(들) 명시
  - 권장 명령 예시 (`/jira-task design <TASK-ID>` 등)
  - 강제 우회 방법 안내 1줄(MAE-124에서 구현 예정 — 메시지 문구만 미리 포함하거나 일반 안내)

## Risks

| Risk | Impact | Mitigation |
|------|--------|------------|
| Claude Code hook payload 스키마(특히 stdin 형식, exit code 의미)에 대한 가정이 틀림 | 높 (게이트 미동작) | design 단계에서 공식 문서 또는 기존 hook(`session-start.js`, `stop-sync.js`) 동작 방식 확인 후 설계 확정 |
| `Skill` 도구 호출 외에 슬래시 명령 직접 호출(`/jira-task impl`)은 PreToolUse를 거치지 않음 | 중 | 본 작업 범위는 Skill 호출 게이팅에 한정. 한계는 README(MAE-127)에서 명시 |
| `fileGlob`을 단순 `{TASK_ID}` 치환 + `fs.existsSync`로 처리 시, 실제 glob 패턴(예: `*`)은 지원되지 않음 | 저 | config 현재 정의에 와일드카드 없음. 필요 시 design에서 minimal glob 처리 추가 검토 |
| `.jira-context.json`이 비어 있거나 손상된 경우 스크립트가 예외로 hook 자체를 깨뜨림 | 중 | try/catch로 모든 IO/파싱을 감싸고, 예외 시 graceful exit 0 (게이트 적용 불가 → 통과로 처리, 보수적이지만 차선) |
| hook timeout(현재 hooks.json의 다른 hook은 10s) 초과 | 저 | 동기 IO만 사용, 외부 패키지 없음, 단순 fs/JSON.parse로 ms 단위 종료 |
| MAE-124(bypass)와 충돌 | 저 | 본 작업에서는 `JIRA_PHASE_GATE_BYPASS` env 검사 분기를 미리 한 줄 넣어두되 동작은 design에서 확정 (확장 포인트 명시) |

## Edge Cases

- **`.jira-context.json` 미존재**: 일반 디렉토리에서 작업 중이라는 신호 → 게이트 비활성, exit 0
- **`completedSteps` 필드 자체가 없음**: 빈 배열로 간주
- **config의 phase 키가 호출된 phase와 매칭 안됨** (예: 새 phase 추가됨): 안전장치로 게이팅 스킵, exit 0
- **호출 phase가 `init`처럼 `requires: []`인 경우**: requires 충족 + artifacts 없음 → 즉시 통과
- **`enforced: false`**: requires/artifacts 평가 자체를 건너뛰고 exit 0
- **TASK_ID 미확인**: `.jira-context.json`은 있지만 `taskId` 필드가 없으면 artifacts 치환 불가 → 보수적으로 게이트 스킵 + 경고 1줄(stderr) 후 exit 0
- **stdin이 비어 있음**: payload 없음 → exit 0 (다른 hook 트리거에서 호출되는 사고 방지)
- **payload가 JSON 아님**: try/catch → exit 0
- **상향 탐색 중 다른 프로젝트의 `.jira-context.json` 발견**: 첫 번째 발견 사용. multi-worktree에서는 cwd에 직접 있을 것이므로 정상 케이스
- **fileGlob의 `{TASK_ID}` placeholder 외 변수**: 현재 config 범위에서는 없음. design에서 확장 정책 결정
