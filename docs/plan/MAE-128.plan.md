# Plan: MAE-128 - [1.3.1] 각 단계별 template 목록 확정 + 섹션 정의

## Background

Phase 1.3 ("Step별 Template 정비")의 1.3.1 sub-task. `/jira-task` 워크플로의 산출물 문서를 정형화하기 위해, 각 단계가 채워야 할 5종 template의 섹션 구조와 contract(필수/선택/형식)를 확정한다.

현재 `templates/`에는 `plan.template.md`, `report.template.md`, `requirements.template.md` 3종만 있으며, design/test-report/review/pr-description 4종이 누락되어 각 스킬이 SKILL.md 인라인 지시로 산출물을 작성하고 있다. 이를 외부 template로 분리하면 (1) 산출물 형식 일관성, (2) template만 수정해서 형식 진화 가능, (3) 신규 사용자가 template만 봐도 스킬 동작 이해 가능 등의 효과를 얻는다.

### Scope Expansion (MAE-129/130/131 흡수)

원래 1.3.x sub-task 4개로 분해되었으나 잘게 쪼개는 것이 메타 작업을 만든다고 판단해 통합:
- **MAE-129 (가변 섹션 정책)**: 흡수 — 별도 정책 문서 X. 템플릿 자체에 `<!-- optional: ... -->` 마커로 표현.
- **MAE-130 (스킬이 template 참조)**: 흡수 — 템플릿 만드는 김에 4개 SKILL.md에 plan 스킬과 동일한 참조 패턴 추가.
- **MAE-131 (CI lint)**: won't do — CI 환경 부재.

## Scope

### In Scope

1. **Template 신규 작성 (4종)** — `templates/` 하위:
   - `design.template.md`
   - `test-report.template.md`
   - `review.template.md`
   - `pr-description.template.md`
2. **Template 검토 (1종)**: 기존 `templates/requirements.template.md` 점검 — 신규 4종과 일관된 표기/구조인지.
3. **SKILL.md 템플릿 참조 규칙 추가 (4개 스킬)**:
   - `skills/jira-task-design/SKILL.md`
   - `skills/jira-task-test/SKILL.md`
   - `skills/jira-task-review/SKILL.md`
   - `skills/jira-task-pr/SKILL.md`
   - 참조 패턴은 `jira-task-plan` SKILL.md의 기존 방식을 따른다(예: "`templates/<name>.template.md`의 구조를 따른다").
4. **가변 섹션 마커 규약 정의**: 모든 신규 template에 `<!-- optional: <조건> -->` 형식의 주석 마커를 사용. 마커는 사람/LLM이 읽고 판단할 수 있는 정도면 충분(자동 lint 없음).

### Out of Scope

- 실제 산출물(docs/design/*, docs/test/*, docs/review/*) 재작성 — 기존 산출물은 그대로 둔다.
- CI lint, 템플릿-스킬 일관성 자동 검증 — MAE-131 won't do로 종결.
- pr-description의 GitHub PR template 통합 — 단순히 `/jira-task pr` 스킬이 사용할 본문 형식만 정의.
- requirements.template.md 신규 작성 — 이미 존재(검토만).

## Acceptance Criteria

### AC-1: 5종 template이 `templates/` 하위에 존재
- Given: MAE-128 작업 완료 시점
- When: `ls templates/`
- Then: `requirements.template.md`, `design.template.md`, `test-report.template.md`, `review.template.md`, `pr-description.template.md` 5개 파일이 모두 존재한다.

### AC-2: 각 template이 섹션 구조와 contract를 명세
- Given: 신규 4종 template
- When: 파일을 읽음
- Then: 각 섹션이 마크다운 헤더로 구분되어 있고, 가변 섹션은 `<!-- optional: ... -->` 마커로 표시되어 있다.

### AC-3: 4개 스킬의 SKILL.md가 template을 참조
- Given: `jira-task-design`, `-test`, `-review`, `-pr` SKILL.md
- When: SKILL.md를 읽음
- Then: 산출물 생성 단계 지시에 "`templates/<name>.template.md`의 구조를 따른다"는 문구가 포함되어 있다.

### AC-4: 기존 산출물의 섹션 패턴이 template에 반영됨
- Given: `docs/design/*.md` 16개, `docs/test/*.md` 16개, `docs/review/*.md` 16개
- When: template과 비교
- Then: template의 필수 섹션은 기존 산출물에서 출현 빈도가 높은 섹션이고, 옵셔널 섹션은 일부 산출물에만 등장하는 섹션이다.

## Edge Cases

- **review.template.md vs review-report.template.md 명명**: Jira 본문은 `review-report.template.md`, 실제 `docs/` 산출물은 `<KEY>.review.md` 패턴. 짧은 쪽인 `review.template.md`로 통일(기존 산출물 패턴과 일치). — design 단계에서 최종 확정.
- **requirements.template.md 위치 차이**: 기존은 `docs/requirements/<slug>.requirements.md` (slug 기반, TASK-ID 없음). 다른 4종은 모두 `docs/<단계>/<TASK-ID>.<단계>.md` (TASK-ID 기반). 검토만 하기로 했으므로 통일은 시도하지 않음 — design 단계에서 차이만 명시.
- **MAE-128 자체의 산출물(design.md, test-report.md, review.md)은 어떤 template를 따르나?** 본 작업이 끝나야 신규 template가 존재함. 본 작업의 design/test/review는 기존 인라인 형식으로 작성되어도 무방. (chicken-and-egg 회피)
- **가변 섹션 마커가 사람만 읽는다는 점**: lint 도구 없으므로 마커는 단순 주석. design.md에서 "마커는 자동 처리 대상이 아니며, 스킬이 LLM 컨텍스트로 참고하는 힌트일 뿐"임을 명시.
