# Design: MAE-260 — 그래프 라이브러리 PoC 및 결정

> 본 문서는 MAE-260 PoC 결과와 채택 결정을 영구 보존하기 위해 main에 박아둔 요약본이다.
> 후속 sub-task(MAE-262~267)가 입력으로 사용한다.

## Overview

Epic MAE-249 (Task 간 연관 관계 Graph View) / Story MAE-252 (그래프 렌더링) 산하 첫 sub-task. 코드 변경 없이 라이브러리 결정만 산출.

**스택 컨텍스트**: dashboard/web은 React 18 + Vite 5 + JSX (TS 미사용), Vitest + jsdom 테스트.

## Decisions

### 1. 그래프 라이브러리: `@xyflow/react` v12 (react-flow)

**대안**: cytoscape.js (+ react-cytoscapejs), d3-force 직접 사용

**선택 이유**:
- React 18 네이티브 — wrapper 경유 없음
- JSX 노드 컴포넌트 자유, edgeTypes 매핑 용이
- 내장 컨트롤·미니맵
- 채점 표 합산 1위

**비용**:
- force layout 비내장 → `d3-force` 추가 의존 필요 (Decision #2)

### 2. Force layout: `d3-force` 추가

**대안**: dagre/elkjs 정적 layout, react-flow 내장 manual

**선택 이유**:
- MAE-249 요구사항이 "force-directed"를 명시
- dagre/elkjs는 트리/계층 layout — 우리의 양방향 의존 그래프에 부적합
- d3-force가 가장 가볍고 검증된 API
- 노드 50 이하(MAE-249 평소 규모 20–50)에서 충분히 부드러움

**구현 패턴**:
```jsx
useEffect(() => {
  const sim = d3.forceSimulation(nodes)
    .force('link', d3.forceLink(edges).id(d => d.id))
    .force('charge', d3.forceManyBody())
    .force('center', d3.forceCenter(w/2, h/2))
    .on('tick', () => {
      setNodes(nodes.map(n => ({ ...n, position: { x: n.x, y: n.y } })));
    });
  return () => sim.stop();  // 메모리 누수 방지: unmount 시 필수
}, [nodes, edges]);
```

### 3. 엣지 styling: react-flow `edgeTypes`로 분리

**규칙**: blocks / parent / epic 각각 별도 edgeType 컴포넌트.

**근거**:
- selector(MAE-261)가 이미 edge에 `type` 필드를 부여한 출력 계약 → edgeTypes 매핑이 자연스러움
- MAE-263 (marching ants 애니메이션) 추가가 1군데 (해당 edgeType 컴포넌트) 수정으로 끝남
- MAE-264 (관계별 색·라벨 차별화) 도 동일 패턴

### 4. 의존성 추가 시점: MAE-262 PR 안에서

**규칙**: `@xyflow/react` + `d3-force`를 `scripts/dashboard/web/package.json`에 추가하는 시점은 **MAE-262 PR**.

**근거**:
- MAE-260은 결정 task — main 코드/의존성에 흔적 0
- 첫 사용자(MAE-262)가 도입하는 것이 dead code 방지에 자연스러움

## Inputs Already in main

후속 sub-task가 그대로 받을 수 있는 자산:

- `scripts/dashboard/web/src/selectors/graph.js` — `selectGraphData(worktrees)` → `{ nodes, edges }` (MAE-261)
  - `node.data.phantom: true` — 다른 worktree에 매핑 안 된 외부 이슈
  - `edge.type: 'blocks' | 'parent' | 'epic'`
  - 노드/엣지 모두 결정적 정렬 (id 사전순)
- `scripts/dashboard/web/src/components/GraphCanvas.jsx` — placeholder (MAE-259)
  - `viewMode === 'graph'`일 때 dashboard-grid 대신 렌더됨
  - props: `worktrees` (정렬·필터링된 목록)

## Implementation Plan for MAE-262

후속 task의 진입점:

1. `npm install @xyflow/react d3-force` (scripts/dashboard/web 안에서)
2. `GraphCanvas.jsx` placeholder 안에 `<ReactFlow>` 컴포넌트 + d3-force simulation 결합
3. `selectGraphData(worktrees)` 호출하여 `{nodes, edges}` 받음
4. `edgeTypes` 객체로 blocks/parent/epic 매핑 (Decision #3)
5. 노드 클릭 → 카드 상세 트리거 (props로 callback 전달 또는 state 끌어올림)
6. unmount 시 `simulation.stop()` (Decision #2)
