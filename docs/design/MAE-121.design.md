## Implementation Plan

| # | 파일 | 변경 내용 |
|---|------|----------|
| 1 | `README.md` (Workflow Mermaid 블록) | `D0["/jira-task discover\n주제 → requirements doc"]` 노드를 추가하고, `D0 -.-> N`(점선)으로 create 노드와 연결. discover는 선택적 단계임을 점선으로 표현 |
| 2 | `README.md` (Workflow 섹션 본문, 다이어그램 직후 안내문 근처) | discover 산출물(`docs/requirements/<slug>.requirements.md`)을 한 줄로 명시. 기존 "Shortcut" 안내 줄 위 또는 아래에 한 줄 추가 |
| 3 | `README.md` (한국어 요약 핵심 특징 목록) | `/jira-task discover [주제]` 항목 한 줄 추가 — 자연어 주제를 요구사항 문서로 변환, `/jira-task create --from-requirements`와 자연 연동임을 명시 |

**노드 ID 규약**: 기존 다이어그램은 `N, A, B, C, D, E, F, G, H, I, J, AUTO` 사용. 신규 노드는 `D0` (discover의 D + 0; 기존 D=design과 충돌 없음 — 단, 가독성을 위해 `DSC`로 변경 검토). 최종 ID는 구현 시 충돌 재확인 후 결정.

**스타일**: 기존 `style N fill:#8B4513` 패턴을 참고해, discover 노드도 동일하거나 인접 색조(예: `#A0522D`)로 지정. 필수 아님 — 가독성만 확보되면 생략 가능.

## Test Plan

자동화 테스트 없음. 수동 검증 체크리스트:

### Manual Verification

| # | 케이스 | 입력/조건 | 기대 결과 |
|---|--------|----------|----------|
| MV-1 | Mermaid 문법 유효성 | GitHub README 미리보기 또는 Mermaid Live Editor에 다이어그램 블록 붙여넣기 | 다이어그램이 오류 없이 렌더링됨 |
| MV-2 | discover 노드 위치 | 렌더된 다이어그램 시각 확인 | discover 노드가 `create` 노드 앞에 표시되고 점선으로 연결됨 |
| MV-3 | 산출물 명시 | README의 Workflow 섹션 본문 검색 | `docs/requirements/` 경로 또는 "requirements doc" 문구가 한 줄 이내에 보임 |
| MV-4 | 한국어 일관성 | `## 한국어 요약 > 핵심 특징` 목록 확인 | discover 항목이 한 줄로 추가되어 영문 섹션과 노출 일관성 유지 |
| MV-5 | 다른 노드 무영향 | 다이어그램 전체 시각 확인 | create/init/start...done 노드와 화살표가 기존과 동일하게 유지됨 |

### Acceptance Criteria 매핑

- AC-1 (다이어그램에 discover 추가) → MV-1, MV-2, MV-5
- AC-2 (역할/산출물 한 줄 설명) → MV-3, MV-4
