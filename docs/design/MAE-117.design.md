# Design: MAE-117 - [1.1.4] templates/requirements.template.md 생성

## Overview

본 설계는 단일 마크다운 파일(`templates/requirements.template.md`) 작성에 대한 경량 설계 문서다. 코드 변경이 없고, discover 스킬의 Inline Fallback Template과 1:1 호환되는 외부 템플릿 파일을 생성해 임시 봉합을 푸는 것이 목표다.

- **Plan 참조**: `docs/plan/MAE-117.plan.md`
- **연관 스킬**: `skills/jira-task-discover/SKILL.md` (Step 4 템플릿 분기)
- **참고 템플릿**: `templates/plan.template.md`, `templates/report.template.md`

## Architecture

### Component Layout

```
templates/
├── plan.template.md          (기존, {...} 표기)
├── report.template.md        (기존, {...} 표기)
└── requirements.template.md  (신규, <...> 표기 - discover fallback과 정합)

skills/jira-task-discover/
└── SKILL.md
    └── ## Inline Fallback Template (180-247줄, 신규 파일과 1:1 매칭)
```

### Decision: 표기 규약 (Plan Task 2)

| 후보 | 사용처 | 채택 여부 | 사유 |
|------|--------|----------|------|
| `{slug}` | 기존 plan/report 템플릿 | X | discover fallback과 어긋남 |
| `<slug>` | discover Inline Fallback Template | **O** | discover 스킬과 1:1 매칭 우선 (AC-3) |

**결론**: 본 템플릿은 `<...>` 표기를 채택한다. 기존 plan/report 템플릿과의 표기 차이는 본 태스크 범위 외이며, MAE-106(Phase 1.3)에서 전체 정비 시 통합 검토할 항목이다.

### Decision: 가변 섹션 안내 방식 (Plan Task 4)

| 후보 | 가독성 | 렌더링 영향 | 채택 여부 |
|------|--------|------------|----------|
| HTML 주석 (`<!-- ... -->`) | 중간 | 마크다운 렌더에서 숨김 | **O** |
| 일반 문구 (이탤릭 등) | 높음 | 산출 문서에 노출됨 | X |

**결론**: discover Inline Fallback이 이미 `<-- --lite 모드면 ... -->` 표기를 사용하므로 동일하게 HTML 주석을 채택한다. 산출물 문서에 안내 문구가 새지 않는다.

## Sequence Diagram

```mermaid
sequenceDiagram
    participant User
    participant Discover as jira-task-discover (Step 4)
    participant FS as File System
    participant Template as requirements.template.md (신규)
    participant Doc as docs/requirements/&lt;slug&gt;.requirements.md

    User->>Discover: /jira-task discover "<topic>"
    Discover->>FS: Read templates/requirements.template.md
    alt 파일 존재 (본 태스크 완료 후)
        FS-->>Discover: 템플릿 본문 반환
        Discover->>Template: 외부 템플릿 베이스로 채택
    else 파일 부재 (본 태스크 완료 전)
        FS-->>Discover: not found
        Discover->>Discover: SKILL.md의 Inline Fallback Template 사용
    end
    Discover->>Discover: Step 1~3 결과로 placeholder 치환
    Discover->>Doc: Write 산출 문서
    Doc-->>User: 요구사항 문서 생성 완료
```

핵심: discover 스킬 코드는 **변경하지 않는다**. 파일 존재 여부만으로 분기되므로 본 태스크는 파일 작성으로 충분하다.

## Section Mapping (Plan Task 1, 5)

discover SKILL.md의 Inline Fallback Template(180-247줄) 구조와 신규 파일의 매핑표.

| # | 섹션 (heading) | 위치 | 비고 |
|---|----------------|------|------|
| 0 | 메타 헤더 (`Slug`/`Mode`/`Generated At`/`Source`) | 파일 상단 (제목 바로 아래) | bullet list 형식 |
| 1 | `## Stakeholders` | 본문 1 | Step 3 답변 1번 |
| 2 | `## Goals & Success Criteria` | 본문 2 | Step 3 답변 2번 |
| 3 | `## Constraints` | 본문 3 | Step 3 답변 3번 |
| 4 | `## Non-functional Requirements` | 본문 4 | Step 3 답변 4번. `--lite`면 "N/A — lite mode" |
| 5 | `## Codebase Context` | 본문 5 | Step 2 결과 |
| 6 | `## Functional Requirements` | 본문 6 | 답변 + 컨텍스트 합성. 번호 매김 |
| 7 | `## Edge Cases` | 본문 7 | **`--lite` 시 생략** (HTML 주석으로 안내) |
| 8 | `## Out of Scope` | 본문 8 | **`--lite` 시 생략** (HTML 주석으로 안내) |
| 9 | `## Open Questions` | 본문 9 | TBD 항목 모음 |
| 10 | `## Proposed Issue Breakdown` | 본문 10 (마지막) | Epic / Story / Sub-task 트리 |

순서·명칭은 fallback과 1:1 동일해야 하며, 차이가 있으면 AC-2 위반이다.

## Implementation Plan

| # | 파일 | 변경 내용 (1-2줄) |
|---|------|------------------|
| 1 | `templates/requirements.template.md` | 신규 작성. 위 Section Mapping 표의 11개 블록을 순서대로 포함. 메타 헤더는 bullet list, 본문 9개 섹션은 `## ` heading, 마지막에 Issue Breakdown 트리 |

상세 작성 규칙 (코드 작성 금지 — impl 단계에서 실제 작성):

- 제목: `# Requirements: <Topic>`
- 메타 헤더 4개 항목을 fallback과 동일 순서로 (`Slug`, `Mode`, `Generated At`, `Source`)
- 각 섹션은 fallback의 **plain-language 안내문**(예: `<Step 3 답변 1번. 주 사용자/호출자/관계자>`)을 그대로 placeholder로 사용
- `Edge Cases`, `Out of Scope` 섹션 위에 `<-- --lite 모드면 이 섹션 통째로 생략 -->` HTML 주석 1줄 (fallback과 동일 문구)
- `Functional Requirements`는 번호 매김 예시 2줄(`1. <Req-1>`, `2. <Req-2>`) 포함
- `Proposed Issue Breakdown`은 Epic 1 / Story 2 / Sub-task 3개의 트리 예시 포함
- 파일 끝 개행 1개 (POSIX 스타일)
- 섹션 간 빈 줄 1개

## Error Handling

본 태스크 자체는 단일 Write 호출이므로 런타임 에러 시나리오가 없다. 다만 사용 측(discover 스킬)에서의 잠재 실패를 짚어둔다.

| 시나리오 | 책임 영역 | 처리 |
|----------|----------|------|
| 빈 템플릿 파일 (헤딩만) | discover 스킬 | discover가 빈 본문을 그대로 사용해 빈 산출 문서 생성 위험 → 본 태스크는 모든 섹션 헤딩과 placeholder를 반드시 포함 |
| placeholder가 산출 문서에 그대로 남음 | discover 스킬 | discover Step 4의 치환 책임. 본 태스크 범위 외 |
| 파일 인코딩/개행 문제 (Windows CRLF 등) | 본 태스크 | UTF-8 + LF로 작성. Write 도구 기본 동작에 의존 |
| `--from` 모드와 충돌 | discover 스킬 | discover Step 4가 보강(merge) 처리. 본 태스크 영향 없음 |

## Security Checklist

본 태스크는 마크다운 정적 텍스트 파일 생성으로, 외부 입력 처리·실행 코드·자격증명 처리가 일체 없다.

- [x] 외부 입력 처리 없음 (placeholder는 정적 안내문)
- [x] 자격증명/시크릿 노출 없음
- [x] 실행 가능 코드 없음 (마크다운만)
- [x] 경로 트래버설 위험 없음 (단일 고정 경로 `templates/requirements.template.md`)
- [x] 의존성 추가 없음

따라서 별도 보안 검토 항목은 없다.

## Test Plan

본 태스크는 코드 변경이 없으므로 자동화 테스트(Unit/E2E)는 작성하지 않는다. 대신 **수동 검증 명세** 4건으로 모든 AC를 커버한다.

### Manual Verification Cases

#### TC-1: 파일 생성 확인 (AC-1)

- **목적**: 파일이 올바른 경로에 비어있지 않은 상태로 존재
- **방법**: `ls templates/requirements.template.md` 및 `wc -l`로 라인 수 확인
- **기대 결과**:
  - 파일 존재 (exit code 0)
  - 라인 수 ≥ 30 (메타 헤더 + 9개 섹션 + 트리 예시)
- **경계 조건**: 라인 수가 비정상적으로 적으면 AC-1 위반

#### TC-2: 섹션 구조 1:1 매칭 확인 (AC-2)

- **목적**: discover Inline Fallback Template과 섹션 명칭/순서가 동일
- **방법**: `grep -n '^## ' templates/requirements.template.md`로 모든 H2 헤딩 추출 후 fallback(SKILL.md 180-247줄)의 H2 목록과 순서대로 비교
- **기대 결과** (순서대로 9개 섹션):
  1. `## Stakeholders`
  2. `## Goals & Success Criteria`
  3. `## Constraints`
  4. `## Non-functional Requirements`
  5. `## Codebase Context`
  6. `## Functional Requirements`
  7. `## Edge Cases`
  8. `## Out of Scope`
  9. `## Open Questions`
  10. `## Proposed Issue Breakdown`
- **메타 헤더 검증**: `grep -E '^- \*\*(Slug|Mode|Generated At|Source)\*\*'`로 4개 bullet 모두 존재 확인
- **경계 조건**: 섹션이 누락되거나 순서가 다르면 AC-2 위반

#### TC-3: discover 스킬 분기 호환 검증 (AC-3)

- **목적**: 파일 존재 시 discover 스킬이 fallback이 아닌 외부 템플릿 분기로 동작
- **방법**: 코드 리뷰 (실 호출은 선택)
  - `skills/jira-task-discover/SKILL.md`의 Step 4 분기 로직 라인을 읽어 다음을 확인:
    - 파일 존재 검사가 `templates/requirements.template.md`을 가리킴
    - 존재 시 외부 파일을 베이스로 사용한다고 명시
- **기대 결과**: 분기 로직이 본 파일 경로를 정확히 참조하며, 파일 부재 시에만 fallback 사용
- **경계 조건**: 분기 로직이 다른 경로를 보고 있으면 AC-3 위반 (다만 본 태스크 범위 외 — discover 스킬 수정은 별도 sub-task)

#### TC-4: --lite 모드 안내 존재 확인 (AC-4)

- **목적**: `Edge Cases`, `Out of Scope` 섹션 위에 `--lite` 생략 안내 주석이 포함됨
- **방법**: `grep -B 1 '^## Edge Cases' templates/requirements.template.md`, `grep -B 1 '^## Out of Scope' templates/requirements.template.md`
- **기대 결과**: 두 섹션 직전에 `<-- --lite 모드면 이 섹션 통째로 생략 -->` 패턴의 HTML 주석 존재
- **경계 조건**: 주석이 한쪽만 있거나 둘 다 없으면 AC-4 위반

#### TC-5: 표기 규약 일관성 검증 (AC-5 + Plan Task 2)

- **목적**: placeholder 표기가 `<...>` 형식으로 일관되며, fallback과 정합
- **방법**: `grep -oE '<[^>]+>' templates/requirements.template.md | sort -u`로 모든 placeholder 추출 후 fallback의 placeholder 목록과 비교
- **기대 결과**: 핵심 placeholder(`<Topic>`, `<slug>`, `<Mode>`, `<Generated At>` 등)가 fallback과 1:1 매칭. `{...}` 표기는 한 곳도 등장하지 않음
- **경계 조건**: `{...}` 표기가 섞여 있거나 fallback에 없는 placeholder가 추가되면 AC-5 의도 위반 (단, 의도적 추가는 변경 사유 명시 필요)

### Acceptance Criteria → Test Case Mapping

| AC | 검증 케이스 |
|----|------------|
| AC-1 (파일 생성) | TC-1 |
| AC-2 (섹션 호환성) | TC-2 |
| AC-3 (discover 분기 호환) | TC-3 |
| AC-4 (`--lite` 안내) | TC-4 |
| AC-5 (Phase 1.3 일관성) | TC-5 |

모든 TC는 review 단계에서 수동으로 실행 가능하며, impl 완료 후 즉시 검증할 수 있도록 구체적인 명령(grep/wc/ls)까지 명세에 포함했다.

## Out of Scope (Design 단계 명시)

- discover 스킬 코드 변경 (별도 sub-task)
- 다른 템플릿 파일(`design.template.md` 등) 작성 (MAE-106 후속)
- CI lint 추가 (MAE-106 sub-task 4)
- `docs/requirements/INDEX.md` 자동 관리

## Notes

- 본 design 문서는 plan에서 합의된 "경량 design"을 따른다. 단일 파일 작성에 대한 과도한 설계는 YAGNI 위반이며, 핵심 결정 사항(표기 규약, 가변 섹션 안내 방식, 섹션 매핑)과 검증 명세만 담았다.
- impl 단계에서는 단일 Write 호출로 본 design의 Implementation Plan을 그대로 실행하면 된다.
