Features

An AI-native lifecycle, not another CRUD bot

Every phase of the SDLC is an agent-executable step — guarded, isolated, and synced.

🔁

Full-lifecycle automation

discover · create · init · start · approach · impl · test · review · merge · pr · done — eleven phases, one harness, one command away.

🌳

Per-task worktree isolation

Every task runs in its own git worktree, so several tasks can move in parallel without ever colliding on a branch.

🚦

Phase-gate guardrails

Hooks enforce step dependencies — you can't jump to impl before the approach is done. Advisory by default, never silently skipped.

🧭

Effort-aware approach docs

One command sizes the work as L1, L2, or L3 and scales the design doc to match. No 10-page spec for a one-line fix.

🔍

Independent code reviewer

A dedicated reviewer sub-agent runs design-vs-implementation gap analysis, lint/format checks, and candid quality review — no self-praise bias.

🔄

Bi-directional Jira sync

Status changes, comments, and attachments post to Jira at every step. Progress is kept on the side, so you can pick up right where you left off after a break.

⚡

Auto mode with self-repair

Run start→review unattended. On a failing review the harness fixes and retries up to twice, and skips phases already completed.

🧠

Cache-first fetching

Once an issue is fetched, it stays in memory. The same session never hits the API twice for the same data.

📊

Relationship dashboard

A force-graph dashboard visualizes blocks, parent, and epic links with status and assignee filters — isolated nodes and cycles surface instantly.

Parallel by Design

Many tasks at once, zero collisions

Each task gets its own git worktree and feature branch, so several flows run side by side without ever stepping on each other. Provision an entire sprint in one command.

  • One isolated worktree + branch per task
  • Batch-provision by count, issue key, or natural language
  • Progress tracked in .jira-context.json across sessions
  • Clean up worktrees and branches when a task is done
