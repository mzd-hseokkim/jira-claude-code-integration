# 글쓰기 규칙

산출물, PR 본문과 코멘트, Jira 코멘트, 사용자 응답에 적용한다. 코드 맥락을 모르는 동료가 한 번 읽고 이해할 수 있게 쓴다.

## 순서

- 결론과 사람이 할 일을 맨 앞에 쓴다. 근거와 수치는 그 뒤에 둔다.
- 실행하지 않은 검사, 확인하지 못한 동작, 남은 위험은 항목 끝에 묻지 말고 따로 적는다.
- 양식에 정해진 절만 쓴다. 양식 밖의 절을 만들지 않고, 양식이 "없음"을 허용하면 한 단어로 끝낸다.

## 문장

- 한 문장에는 한 가지 내용만 담는다. 80자를 넘으면 나눌 수 있는지 본다.
- 한국 사람이 처음부터 한국어로 말하듯 쓴다. 영어 표현이 먼저 떠오르는 문장은 다시 쓴다.
- 주어와 목적어를 생략해 뜻이 흐려지면 밝혀 쓴다.
- 비유와 의인화를 쓰지 않는다. 대시(`—`)로 문장을 잇지 않는다. 문장 중간에 볼드를 넣지 않는다.
- 작업 경위를 늘어놓지 않는다. 지금 유효한 내용만 쓴다.

## 용어

- 새 말을 만들기 전에 제품 화면과 문서에서 쓰는 말을 찾아 쓴다.
- 꼭 새 말이 필요하면 처음 나올 때 뜻을 풀어 쓴다.
- `AC-19`, 커밋 SHA, 테스트 이름처럼 찾아봐야 아는 코드만으로 문장을 끝내지 않는다. 무슨 내용인지 함께 쓴다.
- 표준 조항 코드(`SD-COM-*`)는 사람에게 보이는 글에 쓰지 않는다. 내용을 그대로 말한다.
- 위험 신호는 번호만 쓰지 않고 이름을 함께 쓴다.

## 예시

| 고치기 전 | 고친 뒤 |
|---|---|
| 요청이 `useLlm`을 실어 보내면 입구와 무관하게 그 값이 이긴다 | 요청에 `useLlm` 값이 있으면 업로드든 직접 입력이든 그 값을 따른다 |
| 위험 신호: ② ④ ⑤ | 위험 신호: 외부 API 계약, 인증·권한·개인정보, ADR이 필요한 결정 |
| PR은 draft로 둡니다 (SD-COM-VER-002) | 미충족 조건이 있어 PR을 draft로 둡니다 |

## 예외

- 코드, 파일명, 명령어, 에러 원문은 그대로 둔다.
- plan의 파일 표와 검증 표는 다음 단계의 입력이므로 파일명과 함수명을 줄이지 않는다. 사람을 위한 요약은 승인 요청 코멘트에 쓴다.
