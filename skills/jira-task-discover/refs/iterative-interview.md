# Iterative Interview Loop

`jira-task-discover` Step 3의 반복 인터뷰 본문. SKILL.md Step 3에서 Read 후 그대로 수행한다.

## 카테고리 정의

답변은 항상 아래 4개 카테고리(Q-bucket) 중 하나로 분류된다. 라운드 번호와 무관하게 동일 카테고리의 답변은 같은 bucket에 누적되며, Step 4 trace marker는 `Q1`~`Q4` 인덱스를 그대로 사용한다.

| 인덱스 | 카테고리 | --lite |
|--------|---------|--------|
| Q1 | 이해관계자 | 포함 |
| Q2 | 성공 기준 | 포함 |
| Q3 | 제약 | 포함 |
| Q4 | 비기능 요구사항 (NFR) | **제외** |

`activeCategories` 집합:
- default 모드: `{Q1, Q2, Q3, Q4}`
- `--lite` 모드: `{Q1, Q2, Q3}`

## R0: 카테고리 사전 공지

루프 진입 직전 1단락을 사용자에게 출력 (질문 아님, 단방향 안내):

```
지금부터 요구사항을 라운드 단위로 묻습니다. 다룰 카테고리는 다음과 같습니다:

- 이해관계자 (Q1): 누가 쓰는가
- 성공 기준 (Q2): 무엇을 충족해야 끝났다고 보는가
- 제약 (Q3): 기술/시간/비용/규제 한계
- 비기능 요구사항 (Q4): 성능·보안·접근성·관측성 등   ← --lite 모드에서는 제외

라운드는 최소 4회 / 최대 10회입니다. 6라운드 종료 시 계속 여부를 묻습니다.
```

`--lite` 모드면 위 단락에서 NFR 줄을 제거하고 출력. 그 외 문구는 동일.

## 라운드 루프

상태 변수:
- `roundCount` — 진행한 라운드 수 (정수, 초기 0)
- `bucket: {Q1: [...], Q2: [...], Q3: [...], Q4: [...]}` — 카테고리별 답변 누적 배열
- `MIN_ROUNDS = 4`
- `MAX_ROUNDS = 10`
- `CONFIRM_AT = 6`

### 1라운드 단위 절차

1. **다음 카테고리 선택**
   - `bucket[Q]`가 빈 카테고리 중 `activeCategories` 멤버를 우선 선택 (커버리지 우선).
   - 모두 채워졌으면 LLM 판단으로 가장 깊이 보강이 필요한 카테고리 선택 (예: 답변이 짧거나 모호한 쪽).
2. **질문 1건 생성**
   - 해당 카테고리에 맞는 객관식 옵션 2-4개 + "Other → 자유 입력"을 동반한 질문 1건을 `AskUserQuestion`으로 1회 호출.
   - 질문은 라운드마다 새 컨텍스트(이전 답변)을 반영해 좁혀간다 — 동일 질문 반복 금지.
3. **답변 저장**
   - 답변을 `bucket[Q<N>]`에 append. "Other → (빈)" 응답은 `TBD` 토큰으로 저장 (Step 4 Open Questions 격상 대상).
4. **`roundCount += 1`**
5. **종료 판정** (아래 "종료 조건" 절 참고)

### 종료 조건

각 라운드 종료 후 아래 순서로 판정:

1. **`roundCount < MIN_ROUNDS`** → 무조건 다음 라운드 진행. confirm 묻지 않음.
2. **`roundCount === CONFIRM_AT` (6)** → `AskUserQuestion`으로 confirm 1회:
   - 옵션 A: "계속" → 다음 라운드 진행
   - 옵션 B: "마무리" → 커버리지 검사로 점프 (아래 3번)
   - 응답이 "Other → (빈)"이면 default = "마무리"
3. **커버리지 검사**:
   - `activeCategories` 중 `bucket[Q]`가 빈 카테고리(`uncovered`)를 모은다.
   - `uncovered`가 비어 있으면 → 루프 종료, Step 4 진입.
   - 비어있지 않으면 → `uncovered`에서 1개 카테고리를 골라 **강제 1라운드** 진행 (`MAX_ROUNDS` 한도 안에서). 이 강제 라운드는 사용자 confirm을 묻지 않는다. 강제 라운드 1회로 1개 카테고리만 보강 — 모든 미충족 카테고리를 한꺼번에 묻지 않는다.
4. **`roundCount >= MAX_ROUNDS`** → 강제 종료. 미충족 카테고리는 Step 4 Open Questions에 `[P1] 카테고리 <name> 답변 누락` 형태로 격상.
5. 위 어디에도 해당 안 하면 → 다음 라운드 진행.

### `--from` 모드 보정

`--from <path>`로 import한 본문이 있으면 루프 시작 전 import 본문에서 카테고리별 정보를 추출해 `bucket[Q<N>]`에 `*(source: from)*` 마커와 함께 사전 채움. 이미 채워진 카테고리는 커버리지 검사에서 covered로 간주된다 — 루프는 누락된 카테고리만 묻거나 깊이 보강을 위해 추가 라운드를 돈다. `MIN_ROUNDS`는 동일 적용.

격상 형식 등 구체 규칙은 `refs/conflict-detection.md`(Step 3.5에서 Read) 참고. 본 파일은 인터뷰 루프만 책임진다.

## 출력

루프 종료 시 `bucket` 객체를 Step 4로 전달. Step 4의 합성은 기존 표(Q1-Q4 매핑)와 그대로 호환된다 — 인덱스 체계가 변하지 않으므로 trace marker 규칙도 무수정으로 동작한다.
